### Added
- **Three-valued rule evaluation.**
  Every check now ends as true, false or unknown, and a rule fires only on true.
  A value that a parser marks `Unknown` (new `threatcode.values.Unknown`, a `str` that serializes as `(known after apply)` and carries the reference it could not resolve) makes every operator unknown, so an unresolved value never produces a finding and never counts as a pass.
  On a node whose evidence is `design`, a missing property is unknown instead of absent, so absence rules stop firing on diagrams that never mentioned the property.
  `all_of`, `any_of`, `none_of` and `not` follow Kleene logic, and unknown stays unknown through a negation.
  Parsers do not place `Unknown` values yet; the plan, HCL and CloudFormation parser packages do that.
- **New operators.**
  `equals_ci` compares strings ignoring case and accepts a boolean.
  `any_item`, `all_items` and `none_items` evaluate a condition against each element of a list, which is how a rule can finally look inside Terraform's list-of-object blocks such as `ingress`.
  `is_world_cidr` matches `0.0.0.0/0`, `::/0`, any prefix length 0 network, `*`, `internet` and `any`.
  `port_overlaps` tests a rule's ports against a list of ports and `lo-hi` ranges, for AWS (`from_port`, `to_port`, protocol `-1`) and for Azure style port ranges.
  The shared lists behind them live in the new `threatcode.vocab` (world sources, admin and database ports, dangerous capabilities).
- **Path syntax for nested properties.**
  The longest dotted key that exists wins at each level, so `labels.pod-security.kubernetes.io/enforce` finds that label.
  `labels['a.b']`, `a[0].b`, `a[*].b` and backslash-escaped dots are accepted too.
  A one-element list of blocks is entered without an index, a longer list fans out, and `*` fans out over list elements or mapping values.
- **Rule files are checked when they load.**
  A bad operator (with a "did you mean" suggestion), a condition that mixes a logical operator with property keys, a wrong argument type, a malformed property path, nesting deeper than 10 levels, a malformed `metadata.mitre` and a duplicate YAML key each stop the load with an error that names the file, the rule and the key path.
  Custom rules that used to load and quietly never fire now fail loudly.
- **Resource type forms.**
  A rule names `resource_type` (exact) or `resource_types` (a list), a single trailing `*` makes a prefix glob such as `aws_s3_bucket*`, and `@kubernetes_pod_workloads`, `@kubernetes_long_running` and `@kubernetes_controllers` expand to the matching Kubernetes kinds.
- **Rule fields.**
  `confidence` (`definitive`, `heuristic`, `absence`) and `root_cause` are accepted, a rule file may list removed rule IDs in `deprecated_ids` (read through `deprecated_rule_ids()`), and every rule carries the file it came from as `source_group` (`aws__s3`, `custom__<file stem>`).
- **Kubernetes workload rules cover every pod-bearing kind.**
  The 19 workload rules in `workloads.yml` and the three in `security.yml` used to name only `kubernetes_deployment`.
  21 of those 22 now apply to pods, deployments, daemon sets, stateful sets, replica sets, jobs and cron jobs.
  The liveness and readiness probe rules skip jobs and cron jobs, and `K8S_NO_PDB` stays on deployments.
  A privileged DaemonSet used to produce no findings and now produces the same ones as the Deployment.
- **Golden recordings are split per input.**
  Each input has its own directory under `tests/fixtures/golden/` with `meta.json`, `graph.json`, `findings/<rule file>.json`, `secrets.json` and `model.json`, so packages that re-record in parallel touch different files.
  `scripts/check_golden_scope.py --allow GLOB` fails when a recording outside the globs changed, and `docs/writing-rules.md` was rewritten to cover all of this.

### Changed
- **Breaking: rules match their resource type exactly.**
  A rule with `resource_type: aws_s3_bucket` used to match anything that began with that text, so every S3 rule also ran on `aws_s3_bucket_versioning`, `aws_s3_bucket_policy` and the other companion resources and reported them as unencrypted, unversioned or unlogged.
  Custom rules that relied on the prefix behavior need `resource_type: "aws_s3_bucket*"` or an explicit `resource_types` list.
  The same change removes findings on Key Vault access policies and AKS node pools.
- Plan JSON now agrees with HCL about empty blocks.
  `None`, the empty string, the empty list and the empty mapping count as absent, while `false`, `0` and `"false"` are present.
  Terraform plan JSON writes an unset block as `[]`, which used to count as present.
  Measured on the 228 built-in rules, 78 give a different answer for a property that is present but empty: 75 absence checks now fire, and three presence checks (`AZURE_VM_PUBLIC_IP`, `GCP_IAM_SA_KEY`, `VPC_DEFAULT_SG_OPEN`) now stay quiet.
  None of the 24 recorded inputs has an empty block, so no recording changed for this reason.
- Operators are stricter.
  `equals` does not treat `true` as `1`, `is_true` reads the string `"false"` as false, and `greater_than` and `less_than` take numeric strings (CloudFormation writes numbers that way) and refuse booleans.
  `contains` with a non-string argument against a string is false instead of a `TypeError` that aborted the scan.
- A condition nested deeper than the limit used to evaluate to false, which an odd number of `not` wrappers turned into a match.
  It is now rejected at load time, and at match time it is unknown.
- Loaded rules are immutable and the built-in rules are parsed once per process, using libyaml when PyYAML has it.
  `rule.metadata` and `rule.condition` are read-only containers that still serialize as JSON, and `dict()` or `copy.deepcopy()` gives a plain copy.
  Creating a `HybridEngine` no longer re-reads 51 YAML files.
- `GCP_VM_SERIAL_PORT` compares with `equals_ci`, so `"TRUE"` and a boolean `true` fire it.
- `S3_PUBLIC_ACCESS` also covers `aws_s3_bucket_acl`, and `GCP_VM_DEFAULT_SA` also covers `google_compute_instance_template`.
  Every other built-in rule keeps its single resource type.

### Fixed
- **Rules that read inside nested blocks never matched real Terraform shapes.**
  `CLOUDSQL_*`, `APPSVC_OLD_TLS`, `FUNC_HTTP_V1`, `WAF_NO_DEFAULT_BLOCK`, `CONFIG_NOT_ALL_RESOURCES`, `GUARDDUTY_NO_*`, `SM_LONG_ROTATION`, `MONITOR_SHORT_RETENTION` and `CLOUDRUN_*` use paths such as `settings.ip_configuration.ipv4_enabled`, and Terraform stores each block as a list.
  Cloud SQL with a `maintenance_window`, an App Service with `min_tls_version = "1.2"` and a Cloud Run service with a VPC connector annotation now stay quiet, and their insecure counterparts fire.
- **`K8S_NO_PSA_LABELS` fired on every namespace.**
  The label key contains dots, so the path never resolved.
  A namespace with `pod-security.kubernetes.io/enforce` is now clean.

### Removed
- **The `property_path` operator.**
  It ignored the key it was written under and no built-in rule used it.
  A custom rule that uses it now fails to load with an unknown operator error.
