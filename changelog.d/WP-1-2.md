## Finding, report and engine-phase contracts (WP-1-2)

No scan output changes in this package.
Every new field serializes only when it carries a value, and the golden recordings pass unchanged.

### Added

- `Threat` gains `location_file`, `location_start_line`, `location_end_line`, `fingerprint`, `evidence` (`config`, `design` or `scanner`), `tool`, `aliases`, `target_address`, `effective_severity`, `severity_reason`, `path_ids` and `root_cause`.
  `to_dict` emits each of them only when it differs from its default.
- `ThreatSource` gains `SECRET` and `SCANNER` for secret detector findings and ingested scanner results.
- New `threatcode.models.attack_path` module with `AttackHop`, `AttackPath` and `attack_path_id`.
  A path id is the first 12 hex characters of the sha256 of its node sequence joined with `->`.
- `ThreatReport` gains `attack_paths`, `llm` (provider, model, status `ran`, `skipped` or `failed`, error, threat count) and `rule_errors`, plus `SCHEMA_VERSION = "2"`.
  `attack_paths` and `rule_errors` appear in `to_dict` only when non-empty.
  `llm` appears only when the LLM phase ran or failed; a skipped phase is tracked in memory and not serialized yet.
- `AnalysisContext` (`threatcode.engine.context`) carries secret and ingested scanner findings into `HybridEngine.analyze(graph, input_file, context)`.
  The engine merges them after the rule phase and drops repeated ids.

### Changed

- `HybridEngine.analyze` is now a phase orchestrator: rules, context findings, boundaries, severity, attack paths, LLM.
  Boundary analysis moved to `engine/boundaries.py`, the LLM phase to `engine/llm/phase.py` (`run_llm_phase`), and the severity and attack path phases have their own modules (`engine/severity.py`, `engine/paths.py`) that currently change nothing.
  Threat order and ids are unchanged.
- A rule that raises while evaluating a node no longer aborts the scan.
  The failure is recorded in `report.rule_errors` and logged once per rule.
  Set `THREATCODE_STRICT_RULES=1` to make built-in rules re-raise, which the test suite uses to catch them.
- A failed LLM call is now recorded as `report.llm` with status `failed` and the error, in addition to the existing log line.
  Rule results and exit codes are unchanged.
- Threats produced by one rule no longer share one metadata dict.
  Mutating a threat's metadata cannot reach the rule or the other threats.
- `Severity` ordering now uses `functools.total_ordering` over the severity rank.
  Comparison, equality and hashing behave as before.

### Fixed

- An unknown `stride_category` raises `ValueError` instead of being silently rewritten to `information_disclosure`.
  An unknown `evidence` value raises as well.
