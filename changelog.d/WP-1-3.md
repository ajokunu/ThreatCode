### Added
- **Parser output contract** (groundwork for reworking the parsers).
  `ParsedResource` gains `references`, `start_line`, `end_line`, `mode` and `meta`.
  `ParsedEdge` gains `declared`, and `ParsedOutput` gains `diagnostics`.
  A parser fills in these fields and the graph builder turns them into nodes and edges.
  No shipped parser fills them in yet, so scan output is unchanged and the golden recordings are identical.
- **Diagnostics** (`threatcode.diagnostics`).
  A coverage gap that is not an error, such as a renamed duplicate or a dropped edge, is recorded as a `Diagnostic` with a code from a closed registry.
  Constructing one with an unregistered code raises `ValueError`, and a module that emits its own codes registers them with `register_code`.
  `InfraGraph.diagnostics` collects the parser diagnostics and the ones the graph builder adds.
- **Reference resolution** (`ir/references.py`).
  `ReferenceIndex.resolve` turns a raw reference such as `aws_vpc.main.id`, `${aws_subnet.a.id}-${aws_vpc.main.id}` or `{"Ref": "MyVpc"}` into node ids.
  It takes an exact id first, then the longest known prefix, and fans out to every instance of a counted resource.
  An unqualified reference resolves inside the referring module before the root.
  `var.`, `local.`, `each.`, `count.`, `self.`, `path.` and `terraform.` references name no node.
  A bare name matches `node.name` only when the caller gives the required type and exactly one node of that type has the name.
- **Typed edges from references.**
  A reference in `vpc_id`, `subnet_id`, `security_groups`, `role`, `iam_instance_profile`, `kms_key_id` and their relatives becomes a containment, dependency or iam_binding edge, and only to a node of the right type.
  A `vpc_id` reference to something that is not a VPC adds no edge, and neither does a reference that resolves to nothing.
  A resource that carries references for an attribute no longer gets edges guessed from that attribute's literal value.
  Attributes without references keep the old heuristics until the rule packages remove them.
- **One graph from many inputs.**
  `InfraGraph.from_units` builds a single graph from several parse outputs.
  An address used by more than one input becomes `<input path>::<address>` in every one of them, so the ids do not depend on input order.
  References, dependencies and declared edges resolve inside their own input.
- **Graph limits you can set.**
  `InfraGraph(max_nodes=..., max_edges=...)` and the `THREATCODE_MAX_NODES` and `THREATCODE_MAX_EDGES` environment variables replace the fixed 10,000 and 50,000.
  The node limit error names the variable.
  An edge limit hit now logs one warning with the number of skipped edges and adds a `graph.edge_cap` diagnostic, where it used to log one line per skipped edge.
- **Graph accessors**: `successors`, `predecessors`, `edges_from` and `edges_to`, with an optional edge type filter.
  `STRUCTURAL` and `REACHABILITY` in `ir/edges.py` name the two groups of edge types.
- **Node fields**: `InfraNode` gains `source_file`, `start_line`, `end_line`, `mode`, `exposure` and an `is_container` property.
  `source_file` and the line numbers stay out of `InfraGraph.to_dict`, because that dict feeds the LLM payload.

### Changed
- **Declared edges to unknown nodes are an error.**
  `InfraGraph.from_parsed` raises one `ThreatCodeError` that lists every such edge, with the closest known node ids as hints.
  `InfraGraph.from_parsed(parsed, strict_edges=False)` records each one as a `graph.dangling_declared_edge` warning instead.
  An edge a parser marks `declared=False` is still skipped quietly.
  No shipped parser declares edges yet, so no current scan is affected.
- **A parser cannot forge a trust-boundary crossing.**
  `InfraEdge` has typed `crosses_boundary`, `source_zone`, `target_zone`, `source_boundary` and `target_boundary` fields that only the graph builder sets.
  What a parser says about an edge is kept in `InfraEdge.attributes`, and keys named `crosses_trust_boundary`, `source_zone` or the like in it never reach the computed fields.
  `edge.metadata` keeps the old keys for crossing edges, so existing readers work.
- **The resource type tables moved** into `ir/catalog/` with one module per provider family (aws, azure, gcp, docker, kubernetes, mcp and the lockfile dependency types).
  `ir.nodes` still exports `CATEGORY_MAP`, `TRUST_ZONE_MAP`, `register_category`, `register_trust_zone`, `categorize_resource` and `infer_trust_zone`.
  A parity test holds every entry, and every resource type in the fixtures, to its previous result.
- **Dependencies resolve through the reference index.**
  A dependency on `aws_vpc.main.id` or on a counted resource now finds its node, and a resource never gets a dependency edge to itself.
- `tests/test_security.py` is split by area into `test_llm_security.py`, `test_rule_loader_security.py`, `test_config_security.py`, `test_cli_security.py`, `test_sanitization.py` and `test_graph_limits.py`.
  `test_nodes.py` is split into one test file per catalog family.

### Fixed
- **A duplicate resource address no longer overwrites the first resource.**
  The graph kept only the last resource at an address, so the earlier one and every finding on it disappeared with a debug-level log line.
  Both are kept now, later ones as `<address>#2`, `<address>#3` in input order, with a `graph.duplicate_address` warning.
  `graph.duplicate_of` maps each renamed id to the id it duplicates.
