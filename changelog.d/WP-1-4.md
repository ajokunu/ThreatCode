### Removed
- **The scanning layer that duplicated Trivy, Grype, Syft and OSV-Scanner.**
  ThreatCode builds threat models and attack paths; it does not compete with scanners on breadth.
  The `image`, `vuln`, `db`, `sbom`, `license`, `repo`, `fs` and `secret` commands are gone, so the CLI has two commands, `scan` and `diff`.
  `scan` loses `--scanners` and `--ignore-unfixed`.
  The public functions `scan_secrets`, `scan_vulnerabilities`, `scan_all`, `scan_filesystem`, `scan_repository` and `scan_image` are gone, as are `LOCKFILE_NAMES` and `cvss_to_severity`.
  The modules behind them are deleted: the image scanner (registry client, layer extractor, OS detection, package parsers), the OSV database and OS advisory downloaders, the license scanner, CycloneDX output and the lockfile parser, together with their tests and fixtures.
  The image scanner extracted layers to disk and could be steered into deleting files on the host through whiteouts and symlink chains, and the OSV matcher compared versions with a range model that reported wrong results.
  To scan a repository, clone it and run `threatcode scan <dir>`.
- Stale files: the root `threat_model*.svg` renderings, `tests/fixtures/realistic/output/` (output of version 0.4.3), `bitbucket/pipe.yml` (a commented-out file that is not a pipe) and `OWASP_AUDIT_REPORT.md`.

### Changed
- **The core install is smaller.**
  `anthropic` moves to the `llm` extra and `httpx` and `packaging` are dropped.
  Install the optional model client with `pip install 'threatcode[llm]'`, or everything with `threatcode[all]`.
  A scan that asks for the Anthropic client without the SDK now says `pip install 'threatcode[llm]'` instead of `pip install anthropic`.
- **Terraform plan JSON is claimed more strictly.**
  A plan needs `format_version` together with `planned_values` or `resource_changes`.
  A JSON object that holds only `format_version` is no longer taken for a plan and is reported as an unsupported format.
- **A multi-document Kubernetes file is claimed when any document is a Kubernetes object.**
  It used to be claimed only when every document was one, so a manifest next to a stray YAML document was refused outright.
  Documents that are not Kubernetes objects are skipped.
- **CloudFormation detection no longer needs `AWSTemplateFormatVersion`.**
  A template with a `Transform` (SAM and macros), or a `Resources` section whose resources have a type starting with `AWS::`, `Custom::` or `Alexa::`, is detected.
  The older rule (`Resources` next to `Description`, `Parameters`, `Outputs`, `Mappings` or `Conditions`) still applies.
- **The unsupported-format message lists the supported inputs on short lines** and adds a hint when the file is a JSON or YAML object that none of them recognizes.
- **Error messages drop the exception class name** for errors ThreatCode raises itself, so `Error parsing input file: file is empty: app.yaml` replaces `Error parsing input file: ParseError: ...`.
- The version is single-sourced from `threatcode.__version__`, and the wheel ships the `py.typed` marker.
- Dockerfile detection is one function and also accepts `Containerfile`, `Dockerfile-*`, `Dockerfile_*` and `*.containerfile`, in any letter case.

### Added
- **CloudFormation YAML with short-form intrinsics now parses.**
  `!Ref`, `!GetAtt`, `!Sub`, `!Join`, `!If`, `!FindInMap`, `!ImportValue`, `!Select`, `!Split`, `!Base64`, `!Cidr`, `!GetAZs`, `!Condition`, `!Equals`, `!And`, `!Or`, `!Not` and any unknown tag are turned into the long form (`!GetAtt A.B.C` becomes `Fn::GetAtt: [A, B.C]`).
  Before, any of them failed the scan with "could not determine a constructor".
  Python object tags are still rejected, and unquoted dates such as `AWSTemplateFormatVersion: 2010-09-09` stay text instead of becoming a `datetime.date` that JSON output cannot write.
- **A directory of `.tf`, `.tofu` and `.tf.json` files is scanned as one Terraform module**, and `.tofu` and CDK for Terraform `*.tf.json` files are scanned on their own.
  Resources are concatenated in file-name order; references between resources and expression evaluation are not resolved yet.
- `.template`, `.cfn` and `.json` Kubernetes manifests are accepted, and file extensions are matched in any letter case.
- Input files are read through one decoder: a UTF-8, UTF-16 or UTF-32 byte order mark is honoured (PowerShell redirection writes UTF-16), invalid bytes give `<file> is not valid UTF-8 text`, and an empty or whitespace-only file gives `file is empty: <file>`.
- `-h` works as a help flag, and the `all` extra installs every optional dependency.
- Parser authors get `ParserPriority` (named priorities), a `ParseFileParser` protocol for parsers that read source text, and a duplicate-name check in `register_parser`.
- `parsers/image_ref.py` parses image references (`registry:port/repo:tag@digest`, Docker Hub normalization, build stages, `scratch`, variables) for the Dockerfile, Kubernetes and MCP parsers and for scanner-result ingestion.

### Fixed
- **Terraform state was scanned as an empty plan.**
  `terraform show -json` without a plan file prints state, which has no `planned_values`, so a CI gate built from the docs reported `Scanned 0 resources` and passed forever.
  State JSON now fails with `This is Terraform state, not a plan. Run: terraform plan -out tfplan && terraform show -json tfplan`.
  A plan that only destroys resources fails with `this plan destroys every resource; there is nothing to model`.
- **A crash inside a parser was reported as "Cannot detect format".**
  Once a parser claims a file, any failure is raised as `<parser> parser failed on <file>: <type>: <message>`, with the original exception attached.
- **Files with a byte order mark** failed with `Unexpected UTF-8 BOM` for JSON and could break the first instruction of a Dockerfile.
- Invalid JSON and YAML errors name the file and the line, and HCL errors name the file and line without the parser's token dump.

### Golden recordings
- None changed.
  The 24 recordings under `tests/fixtures/golden/` pass unchanged.
  Lockfiles were never golden inputs, and the registry rework, the YAML loader and the HCL text path produce the same resources for every recorded input.
