### Changed

- **ATT&CK data is generated from the official STIX bundle**: the ATT&CK database is now generated, not hand-written.
  `scripts/gen_mitre_db.py` reads the pinned ATT&CK Enterprise v19.2 STIX 2.1 bundle and writes `src/threatcode/engine/mitre_data.py`.
  `TECHNIQUE_DB` grows from 34 hand-picked techniques to all 858 enterprise techniques and sub-techniques, so any real current technique ID is now recognized.
  `TACTIC_DB` grows from 13 to all 15 enterprise tactics.
- `TECHNIQUE_DB` entries keep `name`, `tactic_ids` and `url` and gain `platforms`, `deprecated`, `revoked` and `revoked_by`.
  `TACTIC_DB` entries gain `shortname`, the ATT&CK Navigator tactic name.
- Revoked and deprecated techniques stay in `TECHNIQUE_DB` with their flags, so rules and input that still carry an old ID keep loading.
- `threatcode.engine.mitre` is now a thin API over the generated data.
  It exports `ATTACK_VERSION`, `TACTIC_SHORTNAME`, `REVOKED_ALIASES`, `normalize_technique()`, `is_revoked()`, `is_deprecated()` and `tactic_shortname()` next to the existing lookups.
- `scripts/gen_mitre_db.py --check` exits 1 when the committed module differs from what the pinned bundle produces.
  `--stix PATH` works offline and `--version X.Y` moves the pin.
- `docs/mitre-attack.md` states the pinned version and how to regenerate.

- No rule was retagged.
  25 builtin rules still carry the revoked T1562.008 and hand-written tactic lists.

  The new tests report the rules that still use a revoked technique as a warning, not a failure.
