### Added
- **Test infrastructure for the rework**: shared helpers and corpora that later packages use to prove their fixes, with no change to scan output.
  `tests/helpers/` holds `graph_assert` (edge, zone, exposure and path assertions whose failure messages list the edges around the nodes in question), `scan` (`scan_text` and `scan_files` run `detect_and_parse`, the graph and the engine the way a scan does), `cli` (a child-process runner for `python -m threatcode`), `plan_shape` (rejects a plan fixture that lacks the parts `terraform show -json` prints) and the `pending(package_id, reason)` marker.
  A pending test is skipped with its reason and never flips between pass and fail on an unrelated merge.
  `THREATCODE_RUN_PENDING=<package id>` runs one package's pending tests, and `THREATCODE_FAIL_ON_PENDING=1` turns any marker left behind into an error.
- **Per-rule bad and good examples** (`tests/test_rules/`): every builtin rule is meant to have a real-syntax example it fires on and its recommended fix it does not fire on, in HCL, plan JSON, CloudFormation, Kubernetes, Dockerfile or MCP config form.
  A case goes through the parser, the graph and `matches_rule` for that one rule on every node, so a typo in a condition key or a rule that never matches its resource type fails.
  A ratchet keeps `tests/test_rules/uncovered/<group>.txt` honest in both directions: a listed rule that gains cases fails until it is removed from the list, and a rule without cases that is not listed fails.
  The lists start with every rule that has no active example (205 of 228 rules).
  A synthetic dead rule, a vacuous good example and malformed case files are covered by self-tests.
  Cases for behavior a later package delivers are written now with a `pending.yml` entry naming the package.
- **Format parity** (`tests/test_rules/test_format_parity.py`): one configuration written as HCL, plan JSON and CloudFormation must trip the same rules, with the known differences listed and pending.
- **Real-shape corpus** (`tests/fixtures/real_shapes/`): Terraform plans in the shape `terraform show -json` prints (unknown values omitted and listed in `after_unknown`, references in the configuration, counted and `for_each` instances, a counted module, split S3 resources, nested blocks, two VPCs), a multi-file HCL module with a local and a remote module call, short-form CloudFormation, SAM, nested-stack and Resources-only templates, `kubectl get -o yaml` and `-o json` lists and every workload kind, the `helm create` scaffold and a chart with subdirectories and a subchart, lowercase, heredoc, multi-stage and ONBUILD Dockerfiles, and MCP configs with wrappers, Windows launchers, `docker -e` secrets, shared project basenames, Gemini `httpUrl` and disabled servers.
  Each directory names its source shape; plans are marked handbuilt because no Terraform binary was available (`scripts/capture_plans.md` explains how to replace them).
  A meta-test fails when a plan fixture claims a `format_version` but has no `resource_changes`, unless it is on an explicit legacy list that may only shrink.
- **Graph tests on real shapes** (`tests/test_ir/test_graph_realistic_{plan,hcl,cfn,k8s,docker,mcp}.py`): node sets, edges, zones, exposure and paths for each fixture.
  Assertions that hold on the current tree run now; each assertion a later package delivers is its own pending test that names the package and the specific deliverable.
- **Planted-issue benchmark** (`tests/test_quality/`): hand-maintained `must_find` and `must_not_find` lists for the ten realistic fixtures, seeded from the 39 issues they plant, and a harness that reports recall, must_not_find violations and companion-resource duplicates per fixture and in total.
  On this tree it measures 20 of 39 planted issues found (51%), 25 violations on hardened or companion resources and 48 duplicate findings on companion resources.
  The tests only assert that the harness runs; a ratchet file records the baseline when a package sets it.
- **Hardened corpus** (`tests/fixtures/real_shapes/hardened/`): one fully hardened Kubernetes, Dockerfile and MCP input each, which must scan with no rule finding; the tests are pending on the packages that own those rules, because today every one reports false positives.
- **Schema conformance** (`tests/test_formatters/test_schema_conformance.py`): SARIF output validates against the vendored OASIS SARIF 2.1.0 schema and ATT&CK Navigator layers against a layer 4.5 schema, for every golden input and two inputs with markup, quotes and mentions in their names.
  MITRE publishes no JSON Schema for layer 4.5, so `tests/fixtures/schemas/attack-navigator-layer-4.5.schema.json` is derived from the layer format document, which is vendored beside it with the source commit and retrieval date.
  GitHub ingestion lints (a region on every result, partial fingerprints, security-severity on every rule) and Navigator semantic checks (no empty tactic, valid shortnames, a full Navigator version) are written and pending on the formatter package.
- **Hostile input corpus** (`tests/hostile/`): generators for unterminated Helm actions, symlink escapes and cycles, FIFOs, single lines of megabytes, JSON and YAML nested 100000 levels deep and a YAML alias bomb, each scanned in a child process under a wall-clock and memory budget.
  Hypothesis property tests (fixed seed) cover JSONC stripping and redaction.
  Inputs the parsers survive today are regression guards; the inputs that hang or crash them are pending on the package that fixes each.
  The budgets are generous (ten seconds, five for the "fast" assertions on 5 MB inputs, which measure about one second locally); on a slow runner raise `DEFAULT_BUDGET_SECONDS` in `tests/hostile/support.py` and `FAST_SECONDS` in the test modules.
- **Demo examples** (`examples/aws-webapp`, `examples/k8s-platform`, `examples/agent-workstation`): a real-shape AWS plan with a real-shape Trivy report, a Kubernetes platform and an agent MCP config, each with an `expected.yml` listing the attack paths from the internet, the nodes in between and the key findings.
  `tests/test_examples_paths.py` and `tests/test_examples_ingest.py` check today that every example parses, models the nodes it names and has the structure its paths rest on; the paths and the ingestion are pending.

### Changed
- `tests/test_engine/test_rule_count.py` no longer asserts that at least 220 rules exist.
  A floor passes while rules sit dead and fails when a rule that could never fire is deleted on purpose.
  The test now checks that every builtin rule file loads, that every rule id is defined once and that the loader returns exactly the rules in the files; totals are printed, not asserted.

Golden recordings are unchanged: every new fixture lives outside `tests/fixtures/realistic` and `tests/fixtures/golden`.
