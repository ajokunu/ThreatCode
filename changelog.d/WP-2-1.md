### Added
- **Terraform plans keep their relationships through `count`, `for_each` and modules.**
  `terraform show -json` writes one configuration entry per resource and one planned entry per instance, so every instance of `aws_instance.app[0]`, `aws_security_group_rule.ingress["https"]` or `module.subnets[1].aws_subnet.this` used to lose every edge the configuration states.
  An instance now inherits the references of its resource, looked up by its address without indexes.
  A reference to a counted or `for_each` resource without an index names every instance, and one with an index names only that instance.
  A reference that matches no planned address is dropped, and nothing is ever bound by name alone.
- **References inside nested blocks are followed.**
  `ingress[].security_groups`, `vpc_config[].subnet_ids`, `root_block_device[].kms_key_id` and deeper paths such as `rule[].apply_server_side_encryption_by_default[].kms_master_key_id` are recorded by path, and the graph turns them into edges.
  Only the top-level attributes were read before.
- **References are scoped to the module they are written in.**
  A resource in `module.net` that reads `aws_vpc.main` binds to `module.net.aws_vpc.main` and never to a root `aws_vpc.main`.
  The instance of the module counts: `module.subnets[1].aws_network_acl.this` binds to `module.subnets[1].aws_subnet.this` and not to the subnet of instance 0.
- **Module inputs and outputs are resolved.**
  `var.vpc_id` inside a module becomes whatever the parent's module call passes for it, through any number of levels, and `module.net.subnet_id` becomes the resource behind that output.
  A module key is honored: `module.tenant["a"].subnet_id` reaches only the subnet of instance `a`, and `module.net.subnet_id` on a counted module reaches every instance.
  A reference chain that loops back on itself, or runs deeper than 50 modules, names nothing.
  A whole module (`module.net`, `depends_on = [module.net]`) names no single resource, so it adds no edge.
- **Values known only after apply are `Unknown`, not missing.**
  The plan lists them in `resource_changes[].change.after_unknown` and omits them from the planned values, so a rule that read the omission saw "not configured".
  The parser puts a `threatcode.values.Unknown` at each of those paths, in nested mappings and block lists too, keeping the reference the configuration wrote for it (`aws_kms_key.trail.arn`, or `var.kms_key_arn` inside a module).
  An attribute that the configuration writes as a reference, with no constant, and that the plan has no value for is unknown as well.
  A planned value is never replaced, and a block is never invented.
  A trail whose `kms_key_id` comes from a key created in the same plan no longer reports `CLOUDTRAIL_NO_ENCRYPTION`, and a trail with no key at all still does.
  One info diagnostic, `plan.unknown_values`, counts them.
- **Data sources are context nodes.**
  A data source in `planned_values` becomes a `mode = "data"` node that rules never evaluate, and a reference to it adds an edge to it.
  One info diagnostic, `plan.data_source`, counts them.
  A data source the plan read while planning (it appears only in `prior_state`) is not modeled.
- **Source lines for plan resources.**
  Each resource carries the plan file as its location and the line its object starts on, found by reading the file again.
  `TerraformPlanParser.parse` takes an optional `text` argument so a caller that already holds the text avoids the second read.
- **A plan with nothing to model is reported.**
  A plan that yields no managed resource adds a `parse.zero_resources` warning that says whether it held data sources only.
- **A limit on resolved references.**
  A reference to a counted resource without an index lists every instance, so a hostile plan could ask for lists as long as the plan for every resource.
  Past 500,000 resolved references the remaining resources resolve nothing and a `plan.reference_limit` warning says so.
  A reference with more than 108 dotted parts names nothing.
- **Four more real-shape plan fixtures and golden recordings for the whole plan corpus.**
  `module_scopes.plan.json` has same-named resources in a root and a module, a nested module, and a `for_each` module.
  `unknown_values.plan.json` has trails and queues with a key known after apply beside ones with no key.
  `azure_network.plan.json` and `gcp_network.plan.json` hold the `azurerm` and `google` shapes (network security group with inline `security_rule` blocks, `google_compute_firewall` with `allow[]` blocks, nested `ip_configuration[]` and `network_interface[]` references) as conformance inputs for the provider rule packages.
  `webapp`, `modules`, `two_vpcs` and the four new plans each have a recording under `tests/fixtures/golden/real_shapes__terraform__plan__*`.

### Changed
- **An `Unknown` that the plan parser places is falsy.**
  It is still recognized by `is_unknown` and still serializes as `(known after apply)`.
  The zone heuristic reads `associate_public_ip_address`, `map_public_ip_on_launch` and `publicly_accessible` by truthiness, and containment inference reads a non-empty `vpc_id` as a literal id.
  A plan marks those attributes unknown on almost every instance and load balancer, so a truthy `Unknown` would have moved each of them into the DMZ and attached them to the first VPC.
- **Plan resources have an empty `module` field.**
  Their references are now full planned addresses from the root, and the graph tries a reference inside the referring module first, so a root resource passed in through a variable would have bound to a same-named resource of the module.
  The module instance is in `meta["module"]`, and `meta` also holds `index`, `count`, `for_each`, `depends_on` and `change_actions`.
- The plan security group fixtures hold `ingress` and `egress` in the shape the AWS provider writes: a list of objects with `cidr_blocks`, `description`, `from_port`, `ipv6_cidr_blocks`, `prefix_list_ids`, `protocol`, `security_groups`, `self` and `to_port`.
  `multi_service_insecure.plan.json` held two groups as a JSON string, which the old rule matched as text.
  The IPv6 group now keeps `::/0` in `ipv6_cidr_blocks` instead of `cidr_blocks`.

### Known gaps
- `SG_UNRESTRICTED_INGRESS` no longer fires on `multi_service_insecure.plan.json`, because it cannot read a list of objects.
  This is the honest interim result until the network rule package rewrites the rule, and a pending test expects both groups to be reported again.
- A bucket in a real plan reports no `S3_NO_ENCRYPTION`, `S3_NO_VERSIONING` or `S3_NO_LOGGING`.
  The AWS provider marks the bucket's `server_side_encryption_configuration`, `versioning` and `logging` as unknown after apply, and the settings live in companion resources the scan does not join to the bucket yet.
  The old findings were false positives whenever a companion resource configured the setting, and a bucket with no companion at all now reports nothing until the companion join lands.
  `ELB_NO_ACCESS_LOGS` and `SM_NO_ROTATION` on the web application fixture disappear for the same reason.
- Boundary findings rise on real plans because the graph now has the edges.
  The boundary pass reports every edge that crosses zones whatever its type, and a pair joined by both a dependency and a containment or iam_binding edge is reported twice with the same id.
  On `webapp.plan.json` the edges go from 23 to 83 and the boundary findings from 6 to 30.
