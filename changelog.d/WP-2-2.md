### Added
- **A directory of Terraform files is one module, with references between its files.**
  `threatcode scan <dir>` reads every `.tf`, `.tofu` and `.tf.json` file in the directory together, so an instance in `main.tf` that names a subnet in `network.tf` gets an edge to it.
  The parser records each reference as `ParsedResource.references` (attribute path to reference strings, `ingress[].security_groups` for a nested block) and `depends_on` as `dependencies`.
  Indexes and splats are dropped, so `aws_subnet.private[count.index].id` names every instance of the counted subnet.
  References inside function calls, conditionals and `for` expressions are found too.
  A single file resolves only the resources, variables and locals it declares itself, and still follows the local modules it calls from its own directory.
  Scanning the directory also reads `terraform.tfvars` and `*.auto.tfvars`, which a single file does not.
- **Variables, locals and simple expressions are evaluated.**
  A variable takes its value from `terraform.tfvars` or `*.auto.tfvars`, then its default, then the input of the `module` block that calls it.
  Locals, string interpolation, arithmetic, comparisons, `&&`, `||`, `!` and ternaries over known values are evaluated, with a few pure functions (`jsonencode`, `merge`, `concat`, `length`, `lookup`, `element`, `join`, `lower`, `upper`, `to*`, `flatten`, `distinct`, `keys`, `values`, `coalesce`).
  Nothing is run: there is no `eval`, no file is read and no provider is called.
  A `publicly_accessible = var.public` with `default = false` is now `false`, so it no longer reads as a public database.
- **Unresolved values are `Unknown`, never absent and never text.**
  An attribute of another resource, a variable with no value, a `for` expression and every function that is not evaluated become `values.Unknown` carrying the reference that could not be resolved.
  A property that used to hold `${var.encrypted}` as text now holds an `Unknown`, so an absence rule such as `CLOUDTRAIL_NO_ENCRYPTION` does not fire on a `kms_key_id = aws_kms_key.trail.arn`.
- **Local modules are followed.**
  A `module` block with a `./` or `../` source is read with its inputs bound, and its resources are addressed `module.<name>.<type>.<name>`.
  A module output used by the caller resolves to what the output names, so `module.net.subnet_ids` becomes an edge to the module's subnets.
  Following is limited to 8 levels and 200 module calls, a module that calls itself is skipped, and symlinked directories and files are never read.
  A `../` source may leave the scanned directory, as real repositories do when an environment directory calls `../../modules/vpc`; only `.tf`, `.tofu` and `.tf.json` files of that directory are read.
- **A remote module is reported, never skipped silently.**
  A registry, git or other non-local `module` call is not read.
  It becomes an `hcl.module_call_skipped` warning that names the source and says to scan `terraform show -json` output, and `ParsedOutput.metadata["incomplete"]` is true with the calls listed under `skipped_modules`.
  A root that only calls registry modules therefore no longer scans to a clean pass.
- **`data` blocks become context nodes** (`mode="data"`, addressed `data.<type>.<name>`), so references to them become edges.
  A `data.aws_iam_policy_document` with literal statements renders to the policy JSON that Terraform would produce, so `assume_role_policy = data.aws_iam_policy_document.x.json` is readable by the policy rules.
- **Policies have one canonical form.**
  A heredoc, a `jsonencode({...})` and an escaped literal (`"{\"Action\": \"*\"}"`) that hold the same document now give the same compact JSON text with sorted keys, which is what Terraform prints.
  `IAM_WILDCARD_ACTION` fires for all of them, where the `jsonencode` form never matched before.
  When a value in the document is exactly one unresolved expression (`Resource = aws_s3_bucket.b.arn`) the property is the structure with an `Unknown` at that leaf, so a rule reads it three-valued; text around an unresolved part of a template (`"${aws_s3_bucket.b.arn}/*"`) stays text with `(known after apply)` in its place.
- **Source lines for every resource.**
  `ParsedResource.start_line` and `end_line` are set for every resource, data and module resource block, so findings and SARIF can point at the block.
  The lines come from a brace-matching scan of the text and are the same under both python-hcl2 versions.
- **python-hcl2 4.3 and 8.x are both supported.**
  The dependency range is `python-hcl2>=4.3,<9`.
  An adapter (`parsers/_hcl_adapter.py`) turns both versions into one shape, and the whole parser suite passes under each.
  8.x reads files that 4.x rejects, such as a conditional with a comparison used as an object value; six unchanged files from terraform-aws-modules are vendored under `tests/fixtures/terraform/hcl/real_modules/` to prove it.
- **`hcl.*` diagnostics** record what was not analysed: `hcl.module_call_skipped`, `hcl.unresolved_reference` (one note per resource that uses a variable or local with no value), `hcl.dynamic_block`, `hcl.count_zero` and `hcl.evaluation_limit`.
  An unreadable file inside a directory is a `parse.failed` error diagnostic.

- **Evaluation limits keep a hostile file cheap to scan.**
  threatcode reads untrusted pull requests in CI, so what evaluation builds is bounded in four ways.
  A string that evaluation builds may not pass 1,048,576 characters.
  A list or object may not pass 10,000 elements, counted through nesting and counted again for every place a shared value is used, so `[local.x, local.x]` weighs what it would print.
  Locals, module inputs, module outputs and `aws_iam_policy_document` documents may refer to each other at most 24 levels deep.
  A value past a limit is `Unknown`, which a rule reads as neither present nor absent, and one `hcl.evaluation_limit` warning says which limit was reached.
  The size checks of one parse also share a budget of 4,000,000 units (one per element visited, one per 64 characters built), so thousands of values just under the limits cannot add up to unbounded work.
  A literal that the file spells out is bounded by the size of the file and is not limited.
  The `dynamic` blocks of one resource may expand to at most 256 blocks in all, nested ones included, because `dynamic` blocks inside each other over 30 elements each would otherwise build 30 to the power of the nesting depth (4 levels took 7 seconds and 270 MB, and 5 levels in a file under 1 KB did not finish).
  A block past the total becomes one block whose iterator values are `Unknown`, the same as a collection that is not known, so the work grows with the depth and not with the product of the lists; one `hcl.evaluation_limit` warning says so.

### Changed
- **Meta-arguments are not properties.**
  `count`, `for_each`, `depends_on`, `lifecycle` and `provider` move to `ParsedResource.meta`, so a rule can no longer read `count` as an attribute.
  A resource with a literal `count = 0` creates nothing and is dropped with an `hcl.count_zero` note.
  A count that is zero only because of a variable default keeps the resource, because a value supplied outside the repository may enable it; one that tfvars or a literal makes zero drops it.
  A count that cannot be known keeps one node flagged `instances_unknown`, and a resource keeps its plain address (`aws_instance.app`, not `aws_instance.app[0]`).
- **`dynamic` blocks become the blocks they generate.**
  A `dynamic "ingress"` over a known list or map becomes one `ingress` block per element with the iterator values filled in, up to 32 blocks, so `for_each = [22, 3389]` gives two blocks with `from_port` 22 and 3389.
  A collection that is not known gives one block whose iterator values are `Unknown`, and so does a block that would take the resource past 256 expanded blocks in total.
  Dynamic blocks nested inside static blocks, as Kubernetes resources write them, are expanded as well.
- **One unparseable file in a directory no longer fails the scan.**
  It is a `parse.failed` error diagnostic and the other files are still read; a single file that cannot be parsed, or a directory in which none can be, still raises `ParseError`.
- **A reference to a resource of the calling module is dropped when the module has a resource of the same address.**
  The graph resolves a name inside a module first, so it would have bound the reference to the module's own resource.
  The dropped reference is noted as `hcl.unresolved_reference`.

### Fixed
- **A few short lines could hang the scan, exhaust memory or crash it.**
  A local that doubles its predecessor (`l1 = "${local.l0}${local.l0}"`, `l1 = concat(local.l0, local.l0)`, `l1 = [local.l0, local.l0]`) took 3.6 seconds at 19 levels, 58 seconds and 243 MB at 23, and never finished at 39.
  Two things grew: the value, which had no size limit, and the reference scan, which read the same local again for every use and so did `2**N` reads.
  Locals, module inputs and outputs, data documents and the references inside them are now worked out once each, and values are limited as described above; the same files finish in under 0.1 seconds.
  A chain of locals that each name the previous one (`l1 = local.l0 + 1`, `l2 = local.l1 + 1`, and so on) overflowed the Python stack at about 100 levels, and `threatcode scan` then failed with `terraform_hcl parser failed on main.tf: RecursionError` for the file and for the directory.
  The nesting is now limited to 24 levels and a `RecursionError` from the deepest levels ends as `Unknown`, so the scan completes and the rest of the file is still analysed.
  A value cut short by the nesting limit is worked out again when it is asked for from a shallower place, so `l7` still comes to 8 when a longer chain through it was cut.
- **A stack overflow while parsing an expression was remembered for the rest of the process.**
  The parse cache kept the "nested too deeply" outcome under the expression text, so the same text read later from a shallower stack stayed unknown.
  It is no longer kept.
- **`distinct` and `toset` were quadratic**, and so was `flatten`; they are linear now, which matters once a list may hold 10,000 elements.
- **A scan of a repository that only used modules reported a clean pass.**
  The module, `data`, `variable` and `locals` blocks were ignored, so a root such as `module "s3" { source = "terraform-aws-modules/s3-bucket/aws" acl = "public-read" }` produced no resources and no warning.
- **Escaped and `jsonencode` policies were mangled.**
  python-hcl2 keeps backslashes in quoted strings and prints `jsonencode` as a Python literal (`{'Action': '*'}`), so the policy rules never matched either form.
- **`True`, `False` and `None` appeared in expression text** because python-hcl2 4.x prints Python literals inside `${...}`; they are `true`, `false` and `null` again before anything reads them.
- **A variable defined as `false` read as public.**
  `map_public_ip_on_launch = var.public` was the text `${var.public}`, which is truthy, so every such subnet was placed in the DMZ.

- `terraform__simple.tf` is unchanged: it has no references.
- `realistic__05_hybrid_vpn_datacenter.tf` gains 40 edges (25 dependency, 11 containment, 4 iam_binding) from references such as `subnet_id`, `vpc_security_group_ids`, `route_table_id`, `gateway_id`, `iam_instance_profile` and `role`.
  Eleven new boundary threats follow from the new edges that cross a trust boundary, for example an instance in the DMZ subnet attached to a management instance profile.

### Known limits
- A chain of more than 24 locals, module inputs or outputs is `Unknown` from the 24th level down, and a reference that only sits beyond that depth is not found.
  Real configurations nest a handful of levels.
- A string that is a literal in the file is never limited, but one that is looked up through a local or variable and passes 1 MiB is `Unknown`.
- A heredoc and a quoted string cannot be told apart in python-hcl2 4.x output, so a string is only unescaped when it is JSON once unescaped.
- python-hcl2 4.x keeps the indentation of a `<<-` heredoc that has a blank line in it; 8.x does not.
