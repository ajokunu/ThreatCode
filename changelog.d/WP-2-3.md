### Added
- **CloudFormation rules finally read CloudFormation properties.**
  The rules are written for Terraform attributes (`storage_encrypted`, `server_side_encryption_configuration`, `vpc_config`), while a template spells everything in PascalCase.
  The parser now translates each resource's properties to the names and shapes the rules read, so an absence rule no longer fires on a property the template sets and a value rule fires on the value the template states.
  `StorageEncrypted`, `PubliclyAccessible`, `BackupRetentionPeriod`, `MultiAZ`, `KmsMasterKeyId`, `VpcConfig`, `DeadLetterConfig`, `BucketEncryption`, `VersioningConfiguration`, `LoggingConfiguration`, `SSESpecification`, `IsMultiRegionTrail`, `EnableKeyRotation` and the other attributes the rules read are translated for 67 resource types, and every other key of any type is snake_cased.
  Blocks take Terraform's shape (a list of one mapping), so a rule can read `vpc_config.0.endpoint_public_access`.
  `AccessControl: PublicRead` becomes `acl: public-read`, `Scheme: internet-facing` becomes `internal: false`, and a `NetworkInterfaces` entry with `AssociatePublicIpAddress` sets `associate_public_ip_address`.
  `SecurityGroupIngress` and `SecurityGroupEgress` become `ingress` and `egress` lists of `{cidr_blocks, ipv6_cidr_blocks, from_port, to_port, protocol, security_groups, prefix_list_ids, self, description}`, the shape a plan holds.
  A standalone `AWS::EC2::SecurityGroupIngress` or `Egress` becomes an `aws_security_group_rule`.
  Policy documents (`PolicyDocument`, `AssumeRolePolicyDocument`, `KeyPolicy`, `RedrivePolicy`, `AccessPolicies`, ECS `ContainerDefinitions`) become compact JSON text with sorted keys, the same text `jsonencode` and a plan produce, so one rule such as `IAM_WILDCARD_ACTION` serves both formats.
  The original properties stay under `properties["_cfn"]`.
  Free-form maps (`Tags`, `Environment.Variables`, nested stack `Parameters`, EKS `Labels`) keep their keys, and a `Tags` list becomes a `tags` mapping.
  `'true'`, `'false'` and numeric strings become booleans and numbers, except for attributes that hold names, identifiers, versions and other text.
- **Intrinsic functions are resolved where the template decides them, and unknown where it does not.**
  A `Ref` to a parameter with a `Default` is the default, a `Fn::If` over `Fn::Equals`, `Fn::Not`, `Fn::And`, `Fn::Or` and `Condition` takes its branch when the parameter defaults decide it, and `Ref AWS::NoValue` removes the property.
  `Fn::Join`, `Fn::Sub`, `Fn::Select`, `Fn::Split`, `Fn::FindInMap` and `Fn::Base64` are evaluated when every part is known, and `AWS::Partition` and `AWS::URLSuffix` are treated as `aws` and `amazonaws.com`.
  A `Ref` or `Fn::GetAtt` to a resource, a parameter with no default, `AWS::Region`, `Fn::ImportValue` and every other intrinsic become `values.Unknown`, which a rule reads as unknown, never as "not configured".
  A `cfn.unresolved_intrinsic` diagnostic carries the count.
- **References between resources become edges.**
  `Ref`, `Fn::GetAtt` (list and dotted form) and `Fn::Sub` (string and list form, `${X}` and `${X.Attr}`) are found anywhere in a resource's properties, inside `Fn::Join`, `Fn::If`, `Fn::Select` and `Fn::Split` too.
  Parameters, pseudo parameters, condition and mapping names, `${!Literal}` and Sub variable names are not references, and `Fn::ImportValue` is recorded in the resource's `meta` and the template's metadata.
  Each reference is keyed by the attribute that holds it after translation (`vpc_id`, `subnet_id`, `vpc_security_group_ids`, `ingress[].security_groups`, `vpc_config[].subnet_ids`, `role`, `iam_instance_profile`, `kms_key_id`), which is what lets the graph make a containment, security group or IAM binding edge instead of a plain dependency.
  A subnet is contained in its VPC, an instance in its subnet, a Lambda function in the subnets of its `VpcConfig`, and a function is bound to its role.
- **A complete CloudFormation to Terraform type table** (`parsers/_cfn_types.py`, 142 CloudFormation types).
  It replaces the 18 entries and the snake_case guess, which named `AWS::EC2::NatGateway` `aws_ec2_nat_gateway`, `AWS::Logs::LogGroup` `aws_logs_log_group` and `AWS::ElasticLoadBalancingV2::Listener` `aws_elasticloadbalancingv2_listener`, none of which the rules or the catalog know.
  A type with no entry keeps its CloudFormation name (`AWS::Foo::Bar`) and a `cfn.unmapped_type` diagnostic, and `Custom::*` resources get the provider `custom`.
  `AWS::EC2::VPCGatewayAttachment` is an `aws_vpn_gateway_attachment` when it names a VPN gateway.
- **`python scripts/gen_cfn_type_coverage.py --check`** fails when a built-in rule resource type has no CloudFormation mapping and is not listed in `UNSUPPORTED_IN_CFN` with a reason (today `aws_default_security_group` and `aws_s3_bucket_acl`).
  Without `--check` it prints the support matrix as Markdown, or JSON with `--format json`, for the documentation.
- **AWS SAM templates are expanded** (`parsers/_sam.py`).
  `Transform: AWS::Serverless-2016-10-31` is read, and `AWS::Serverless::Function` becomes an `aws_lambda_function` with its implicit `aws_iam_role` (`<Function>Role`).
  `Policies` entries become managed policy ARNs (`AdministratorAccess` is `arn:aws:iam::aws:policy/AdministratorAccess`), inline policies (a statement document) or, for a SAM policy template such as `DynamoDBCrudPolicy`, a policy whose document is unknown, reported with a `cfn.sam_policy_template` diagnostic.
  An explicit `Role` suppresses the implicit one, and `Globals` are merged the way SAM does.
  Each `Events` entry adds what SAM adds: the implicit `ServerlessRestApi` or `ServerlessHttpApi`, an `aws_lambda_permission`, an event source mapping or subscription, or an events rule, and an edge from the API to the function.
  A `FunctionUrlConfig` becomes an `aws_lambda_function_url`, and one with `AuthType: NONE` gets the public permission.
  `AWS::Serverless::Api`, `HttpApi`, `SimpleTable`, `StateMachine` and `LayerVersion` become the API Gateway, DynamoDB, Step Functions and Lambda resources they stand for, and `AWS::Serverless::Application` stays a nested stack.
  The expansion is deterministic, and every generated resource records the SAM resource it came from in `meta["sam_origin"]`.
- **Every resource carries its source lines.**
  `start_line` and `end_line` come from the YAML and JSON line indexes, so a finding can point at the resource that causes it.
  A generated SAM resource uses the lines of the resource it came from.
- **Nothing the parser cannot model is dropped silently.**
  An entry that is not a mapping, a `Type` that is not a string (the shape of a `Rain::Module`), `Properties` that are not a mapping and an `Fn::ForEach` loop are skipped with a `cfn.skipped_resource` warning that names the entry and the line.
  A template whose entries are all skipped reports `parse.zero_resources`.
  `Resources` as a list is an error that says so.
  An `AWS::CloudFormation::Stack` keeps its node and gets a `cfn.nested_stack` warning, and the output metadata is marked `incomplete`.
  A template-level `Transform` other than SAM is reported as not expanded.
- `CloudFormationParser` also has `parse_text` and `parse_file` for direct callers.
  A template read through them gets the same line numbers as one read through the registry.
- Fixtures: `secure_stack.yml`, `hardened_stack.yml`, `graph_stack.yml` and its long-form twin `graph_stack.json`, `sam_function.yaml` and `minimal.yaml` under `tests/fixtures/cloudformation/`.

### Changed
- **Resource types the CloudFormation parser names differently.**
  `AWS::CloudTrail::Trail` is `aws_cloudtrail` (was `aws_cloudtrail_trail`), `AWS::Logs::LogGroup` is `aws_cloudwatch_log_group` (was `aws_logs_log_group`), `AWS::CloudWatch::Alarm` is `aws_cloudwatch_metric_alarm`, `AWS::RDS::DBSubnetGroup` is `aws_db_subnet_group` (was `aws_rds_db_subnet_group`), `AWS::ElasticLoadBalancingV2::Listener` and `TargetGroup` are `aws_lb_listener` and `aws_lb_target_group`, `AWS::EC2::SubnetRouteTableAssociation` is `aws_route_table_association`, `AWS::IAM::ManagedPolicy` is `aws_iam_policy`, and the rest of the table above.
  The 18 types the old table named explicitly keep their names.
- **`ParsedResource.dependencies` leaves out a target that a typed edge already covers.**
  A reference in `vpc_id`, `role`, `subnet_ids` and the other attributes the graph attaches by type becomes a containment, security group or IAM binding edge to a node of the right type, and listing the target as a dependency too would add a second, untyped edge between the same pair.
  The boundary analysis draws a threat per edge and hashes its id from the pair, so the duplicate doubled every threat on it and made two threats share an id.
  A reference the typed rule rejects (a nested stack in `subnet_id`) and every reference at an untyped attribute stay dependencies, together with `DependsOn`.
  The decision reads the graph's own `ATTACHMENT_RULES`, so the two cannot disagree; if the table disappears, nothing is left out.
- CloudFormation properties are no longer the template's keys: code that read `properties["AccessControl"]` reads `properties["acl"]`, or `properties["_cfn"]["AccessControl"]`.
- The format version and description in the output metadata are always text, and the metadata may also carry `transform`, `sam`, `imports`, `incomplete` and `unresolved_intrinsics`.

### Fixed
- **Absence rules fired on every CloudFormation resource.**
  `S3_NO_ENCRYPTION`, `S3_NO_VERSIONING`, `S3_NO_LOGGING`, `RDS_NO_ENCRYPTION`, `RDS_NO_BACKUP`, `LAMBDA_NO_VPC`, `LAMBDA_NO_DLQ`, `SQS_NO_ENCRYPTION`, `SQS_NO_DLQ`, `SNS_NO_ENCRYPTION`, `DYNAMODB_NO_ENCRYPTION`, `DYNAMODB_NO_PITR` and `DYNAMODB_NO_AUTOSCALING` read a Terraform name that no template has, so they reported "missing" for a resource that set the property.
  38 such findings disappear from the three realistic templates (see the table).
- **Value rules never fired on CloudFormation.**
  `S3_PUBLIC_ACCESS` (a bucket with `AccessControl: PublicRead`), `RDS_PUBLIC_ACCESS` (`PubliclyAccessible: true`), `IAM_WILDCARD_ACTION` and `IAM_OVERPERMISSIVE_ROLE` now fire on a template, with the same rule ids and the same findings as the equivalent Terraform plan.
  The planted public bucket of `realistic/03_aws_data_pipeline.yaml` and of `06_aws_serverless_api.yaml` is found.
- **The two CloudTrail findings of `realistic/09_aws_healthcare_hipaa.yaml`** (dropped when rules started matching resource types exactly) stay absent for the right reason now: the trail is an `aws_cloudtrail`, and its key and bucket are references, which are unknown and never read as missing.
- **A SAM template without `AWSTemplateFormatVersion` produced a bare function with no role, permission or API**, so the privilege of the function (an `AdministratorAccess` policy) was invisible.
- A template with `Resources` as a list, a `Type` that is a mapping or an entry that is not a mapping crashed or was skipped without a word.
- An unquoted `AWSTemplateFormatVersion` date and an unquoted policy `Version` date are text in every output.

### Known limits
- `SG_UNRESTRICTED_INGRESS` reads `ingress` as a list of strings, and `ingress` is a list of objects here as in a Terraform plan, so it does not fire on a template, a plan or HCL until the security group rules are rewritten on `any_item` and `is_world_cidr`.
- Provider defaults are not filled in: a CloudFormation `BackupRetentionPeriod` that is not set still reads as absent, although the service defaults it to one day.
  The rule packages add those defaults.
- Nested stacks are not followed, and the intrinsics that need the deployed stack (`Fn::GetAtt`, `Fn::ImportValue`, `AWS::Region`) stay unknown.
- A mapped attribute holding an `Unknown` in `map_public_ip_on_launch`, `associate_public_ip_address` or `publicly_accessible` is still read as true by the zone heuristic of the catalog, because an `Unknown` is a non-empty string.
  No shipped fixture sets one of these from a value the template cannot decide.
