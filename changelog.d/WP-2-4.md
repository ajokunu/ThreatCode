### Added
- **Every Kubernetes workload kind is read into one property shape.**
  Pod, Deployment, DaemonSet, StatefulSet, ReplicaSet, Job and CronJob (whose pod spec sits under `jobTemplate.spec.template.spec`) now produce the same security properties for the same pod spec, so a rule written once applies to all of them.
- **Security settings are the effective ones.**
  A container value wins over the pod value for `runAsNonRoot`, `runAsUser` and the seccomp profile, a non-zero `runAsUser` means non-root when `runAsNonRoot` is unset, and an explicit `runAsNonRoot: false` on a container beats a pod that says true.
  Containers fold into the workload with one rule: the workload is unsafe when any applicable container is unsafe, capabilities count as dropped only when every container drops `ALL`, and the result does not depend on container order.
  Security checks cover regular, init and ephemeral containers; probes and resource limits cover regular containers and sidecars (init containers with `restartPolicy: Always`), so a pod with only init containers gets no probe findings.
- **New workload properties.**
  `container_findings` maps a property to the containers that make it unsafe (`{"privileged": ["log-shipper"]}`), `images` lists the image references, `seccomp_profile_type` and `has_seccomp_profile` give the effective seccomp profile, `has_cpu_limit`, `has_memory_limit` and `has_ephemeral_storage_limit` split the resource limits (`has_resource_limits` is now cpu and memory together), `effective_automount_sa_token` and `sa_resolved` settle token mounting across the pod and its ServiceAccount, `ingress_policy_covered` and `egress_policy_covered` say whether a NetworkPolicy of the same input selects the workload (with `policy_scope: single-input`), and `pod_labels`, `replicas`, `secret_refs`, `config_map_refs` and `pvc_refs` describe what the workload is and reads.
  The existing property names are unchanged, so no rule file changed.
- **Kubernetes manifests now have edges.**
  An Ingress routes to its backend Service (`network_flow`, `backend`, the legacy `serviceName` too), a Service selects the workloads whose pod labels contain its selector (`network_flow`, `selects`), a workload reads its Secrets, ConfigMaps and PersistentVolumeClaims (`dependency`: `mounts`, `env_from`, `secret_key_ref`, `config_map_key_ref`) and runs as its ServiceAccount (`iam_binding`, `runs_as`), a RoleBinding or ClusterRoleBinding grants its Role or ClusterRole (`iam_binding`, `grants`) and names its ServiceAccount subjects (`bound_subject`), and a NetworkPolicy selects the workloads it covers (`dependency`, `policy`).
  Matching is by namespace, and `matchExpressions` (`In`, `NotIn`, `Exists`, `DoesNotExist`) are evaluated.
  The edges are inferred, not declared, so a target that is not in the input is dropped without an error.
- **RBAC and Ingress properties.**
  Roles and ClusterRoles carry `has_wildcard_api_groups`, `has_escalation_verbs` (escalate, bind, impersonate), `has_secrets_read` and `has_pod_exec`; bindings carry `binds_unauthenticated_group`, `binds_authenticated_group` and `subject_kinds`; an Ingress carries `has_tls`, `has_rules` and `ingress_backends`.
  Rules whose `verbs`, `resources` or `apiGroups` are not lists no longer stop the scan.
  `K8S_INGRESS_NO_TLS` fires for the first time, because `has_tls` now exists.
- **`List` and `<Kind>List` documents and kubectl JSON.**
  `kubectl get ... -o yaml` and `-o json` output is flattened into one resource per item (five levels deep at most, 20,000 documents at most), and a `.json` manifest is claimed.
  A file that mixes Kubernetes objects with other YAML parses the objects and reports each skipped document as a `k8s.skipped_document` warning and under `metadata['skipped_documents']`.
- **Resources carry their file and line.**
  Kubernetes resources set `source_location` and `start_line` (the registry hands the parser loaded values, so the parser reads the file once more for the line index; inputs over 2 MB have no lines).
  Resources rendered from a chart point at their template file and line.
- **A real Helm renderer for when `helm` is not installed.**
  It reads `Chart.yaml` and `values.yaml` and evaluates `.Values`, `.Chart` and `.Release`, `if`, `else if`, `with`, `range`, variables, `define`, `include` and `template`, `toYaml` with `indent` and `nindent`, and the Sprig functions charts use.
  It walks `templates/**` (not `_*.tpl`, `NOTES.txt` or `templates/tests/`) and renders subcharts under `charts/` with their scoped values, `global` values, aliases and `condition`.
  The `helm create` scaffold renders into its Deployment, Service and ServiceAccount, `ingress.enabled: false` drops the Ingress, and an image comes from `values.yaml` with its real tag.
  A value the chart does not give prints as `placeholder-<template>-<document>-<n>`, so two Deployments named from different values never share an address, and an image that is such a token is not reported as untagged.
- **The renderer in use is never silent.**
  Every fallback, whether the binary is missing, `helm` exits non-zero (with the tail of its stderr), times out or prints too much, adds a `helm.fallback_render` warning, sets `metadata['render']` to `fallback` or `helm`, records the reason in `metadata['render_reason']` and logs a warning.
  A template that was skipped or only approximated adds a `helm.render_warning`.
  `THREATCODE_HELM` (or `HelmParser(helm=...)`) is `auto` (default), `off` (always the fallback) or `required` (a missing or failing helm is a `ConfigError`).
- New diagnostic codes `helm.render_warning` and `k8s.truncated_value`.
- `parsers.kubernetes.ManifestDocument` and `KubernetesParser.parse_documents`, which parse documents that were loaded elsewhere as one connected set.

### Changed
- **Breaking: cluster-scoped kinds have no namespace in their address.**
  `Namespace`, `ClusterRole`, `ClusterRoleBinding`, `PersistentVolume`, `StorageClass`, `CustomResourceDefinition`, `Node` and the other built-in cluster-scoped kinds are `<type>.<name>`, for example `kubernetes_cluster_role.admin` instead of `kubernetes_cluster_role.default.admin`.
  Their `namespace` property is now `None`.
  A suppression, baseline or diff that names the old address must be updated.
- **Zones follow what a resource exposes.**
  A Service is `dmz` for `LoadBalancer` and `NodePort`, `internet` for `ExternalName` and `private` for `ClusterIP`; an Ingress with no rule and no default backend is `private`; a ConfigMap is `private` (a Secret stays `data`) and a PersistentVolumeClaim is `data`.
  A node with no `service_type` or `has_rules` keeps the old static zone.
- **Unnamed objects are named, not merged.**
  A missing `metadata.name` becomes the `generateName` stem plus `-generated`, else `unnamed-<document index>`, where it used to become `unknown`.
  Two objects that still share an address are both kept (`#2` suffix) and both get their findings.
- **Kubernetes resource types for kinds the parser had no table entry for are snake case**, for example `kubernetes_horizontal_pod_autoscaler` and `kubernetes_pod_disruption_budget`, where they used to be `kubernetes_horizontalpodautoscaler`.
- **Image tags are judged by the shared image reference parser.**
  `registry:5000/app` is untagged, a digest pin is never floating, and `stable`, `main`, `edge` and the other moving tags count as floating, not only `latest`.
- **Dangerous capabilities come from `threatcode.vocab.DANGEROUS_CAPABILITIES`** (`ALL`, `SYS_ADMIN`, `SYS_PTRACE`, `SYS_MODULE`, `SYS_RAWIO`, `SYS_BOOT`, `BPF`, `PERFMON`, `NET_ADMIN`, `NET_RAW`, `DAC_OVERRIDE`, `DAC_READ_SEARCH`, `MKNOD`, `SETUID`, `SETGID`, `CHOWN`), spelled with or without `CAP_` and in any case.
- `secret_env_vars` and `dangerous_capabilities` are sorted lists without repeats.
- `helm template` is run as `helm template release <chart> --skip-tests`, the same release name the fallback uses, so both renderers give a resource the same address.
  It reads its output through a bounded reader inside its own process group (20 MB, 30 s) and attributes each document to its template through the `# Source:` comments.
- The Helm fallback is a linear scanner and evaluator with caps: a template file over 2 MB is skipped, a line over 64 KB is replaced by a comment, an action over 8 KB is not evaluated, and a chart has step, output and time budgets.
  The old pattern-based scrub took quadratic time on an unterminated `{{`; 80 KB of them held a scan for fourteen seconds.

### Fixed
- Workload rules saw only the last or the first container, ignored pod-level `securityContext` and read `initContainers` as if they were regular containers.
- A `List`, `DeploymentList` or `kubectl -o json` manifest was one node called `unknown`, or was not claimed at all.
- `image: null`, `jobTemplate: null`, `resources` given as a string and other malformed fields crashed the parser.
- The Helm fallback crashed on the `helm create` scaffold, dropped templates in subdirectories and subcharts, and gave every templated resource the address `placeholder`, so all but one disappeared.
- The Helm fallback ran after a failing helm with only a debug message.
