## Dockerfiles: a BuildKit-faithful lexer, a stage model and honest Docker rules (WP-2-5)

### Fixed

- **Lowercase and mixed-case instructions are read.**
  `from`, `run`, `user` and `healthcheck` used to be ignored, so a Dockerfile that set all of them reported a missing USER, HEALTHCHECK and WORKDIR.
  Keywords match case-insensitively and a lone keyword such as `RUN` no longer breaks the parse.
- **Comments, continuations and line numbers follow BuildKit.**
  A comment line inside a `RUN` continuation is dropped and the rest of the command is kept, so later commands in the same `RUN` are analysed.
  A comment that ends in a backslash no longer swallows the next instruction.
  Line numbers are physical lines of the file, where a continuation used to shift every later instruction up (an `EXPOSE` on line 11 was reported on line 6).
  Lines are split on newline only, so a form feed or a Unicode line separator cannot shift them either.
  The `# escape=` directive is honoured, so a Windows `WORKDIR C:\app\` under `` # escape=` `` no longer eats the `USER` that follows.
- **Heredocs are understood.**
  The body of `RUN <<EOF` is analysed with the command (curl piped to a shell and `sudo` inside it are found), and the body of `COPY <<EOF` is never read as instructions, where a line such as `USER root` or `EXPOSE 22` used to become a real node and a real finding.
  A heredoc marker with no terminator is not a heredoc, so a stray `<<` cannot swallow the rest of the file.
- **The image summary describes the image that runs.**
  `has_user`, `user_value`, `is_root_user`, `has_healthcheck`, `has_workdir`, `exposed_ports` and `base_image` come from the final build stage, following `FROM <stage>` inheritance.
  A `USER` or `HEALTHCHECK` in a build stage used to hide a root final stage with no health check, and `base_image` was the builder image.
- **`FROM` is parsed per grammar.**
  `FROM --platform=$BUILDPLATFORM golang:1.22` no longer takes the flag as the image.
  `FROM scratch` and `FROM <earlier stage>` are not registry images and never set `uses_latest_tag`.
  `registry.local:5000/team/app` is untagged instead of tagged `5000/team/app`.
  `ARG TAG=latest` before the first `FROM` is substituted into `FROM base:${TAG}`, so a real latest tag is found.
  A tag that comes from a variable with no default is `Unknown`, which never fires `DOCKER_LATEST_TAG`.
  A digest-pinned image is not latest.
- **Every spelling of root is root.**
  `USER 0:0`, `root:root`, `0:root`, `ROOT` and `00` all set `is_root_user`.
  A user taken from an unresolved variable is unknown, not root.
  `ARG` and `ENV` values are substituted into `USER` and `EXPOSE` when they have a default.
- **`DOCKER_RUN_CURL_PIPE` and `DOCKER_RUN_SUDO` read commands, not text.**
  The `RUN` text is split on unquoted `|`, `&&`, `;`, `&` and newlines, and a download piped into `sh`, `bash`, `zsh`, `dash`, `ash`, `ksh`, `python`, `python3`, `perl`, `ruby` or `node` is flagged, also behind `sudo`, `env`, `command`, `exec` and `VAR=value` prefixes.
  `curl ... | sha256sum -c`, `| tar` and `| gpg` are no longer flagged, and `wget ... | sudo bash` and `curl ... | python3` are now.
  `sudo` counts only as a command word: `apt-get install -y sudo`, `pseudo` and `command -v sudo` no longer fire, and `env sudo make` now does.
  The check is linear, so a single 1.4 MB `RUN` line is scanned in a fraction of a second.
- **`ENV` and `ARG` secrets.**
  Every `KEY=VALUE` pair of a line is inspected, quote-aware and in the legacy `ENV KEY value` form, where only the first used to be.
  A name looks like a secret when a whole word of it (split on `_`, `-` and camelCase) is password, passwd, secret, token, apikey, credential, or when api, private or auth form a pair with key or token, or `key` appears with api, secret, private or access.
  `AUTHOR`, `KEYBOARD_LAYOUT`, `PUBLIC_KEY_PATH`, `SECRET_NAME`, `SECRET_FILE` and `KEY_VERSION` no longer fire, and names ending in a path, file, url, name or id word never do.
  The value matters: an empty value, a placeholder such as `changeme`, a path such as `/run/secrets/db` and a variable reference are not flagged, and `ARG TOKEN` with no default is informational only.
  The resource lists the key names and the kind of each value, never a value, and the value of a flagged key is masked as `<redacted>` in the instruction text and name.
- **`ADD` and `COPY` arguments.**
  One tokenizer reads `--flag[=value]` options, the JSON-array form and sources versus destination.
  `ADD --checksum=... https://...` is a URL add, not a local add, and `ADD --chown=app:app server.pem` and `COPY ["server.key", "/etc/"]` find the sensitive file.
  `has_chown` means `--chown` only, not `--chmod`.
  `DOCKER_ADD_INSTEAD_OF_COPY` no longer fires for a local archive (`ADD rootfs.tar.gz /`), which is what `ADD` is for.
  `DOCKER_COPY_NO_CHOWN` is judged on the final stage only, skips `COPY --from`, and fires only when the image runs as a known non-root user.
- **`EXPOSE` ranges and variables.**
  `EXPOSE 8000-8010 ${PORT} 22-25` used to give no ports at all.
  Ports are stored per instruction, ranges as `[lo, hi]` pairs that are tested by membership and never expanded, and an unresolved `${VAR}` is kept as an unknown-port marker.
  `has_ssh_exposed` is true for port 22 inside a range.
- **The `ENV` rule description** no longer says "ENV or ARG"; `DOCKER_ARG_SECRET` covers `ARG`.

### Added

- **A stage model.**
  Every `FROM` opens a stage.
  Each instruction resource gets the properties `stage` and `onbuild`, and a synthetic `dockerfile_stage` node (`dockerfile.stage.<name or index>`) summarizes the stage's base image, tag, digest pin, user, ports and health check.
  Containment edges run from each instruction to its stage, and dependency edges between stages carry the relation `base` for `FROM <stage>` and `copy_from` for `COPY --from=<stage or index>`.
  All of them are inferred edges (`declared` is false).
- **Summary properties.**
  `has_digest_pin`, `is_non_minimal`, `base_kind`, `final_stage_uses_latest_tag`, `stage_count`, `exposed_port_ranges` and `unknown_exposed_ports` join the existing names, which are unchanged.
  `uses_latest_tag` stays true when any stage uses a floating tag (latest, stable, edge, nightly and the other tags the shared image-reference module treats as moving, or no tag).
  `is_non_minimal` is true for a full distribution image (ubuntu, debian, centos, fedora, amazonlinux, rockylinux, almalinux, oraclelinux, sles) without a slim, minimal, alpine, distroless or busybox marker; language runtime images are not judged.
- **Instruction properties.**
  `ADD` gets `is_url_add`, `has_checksum`, `sources` and `destination`; `COPY` gets `from_stage`, `chown_missing`, `sources` and `destination`; `RUN` gets `has_apt_no_clean` and `heredoc_body`; `EXPOSE` gets `ports`, `port_ranges` and `unknown_ports`; `ENV` and `ARG` get `keys`, `pairs`, `secret_keys`.
- **`ONBUILD <INSTRUCTION>` is unwrapped** into the inner instruction with `onbuild` set.
  Command-level rules (curl piped to a shell, `sudo`) run on the trigger, and the image summary ignores it, because a trigger runs in a child build.
- **Diagnostics.**
  `dockerfile.skipped_line` (warning) for a line that is not an instruction, and `dockerfile.unresolved_variable` (info) for a `FROM`, `USER` or `EXPOSE` value that depends on a variable with no default.
- **Four dead rules are revived** on properties the parser now emits: `DOCKER_NO_DIGEST_PIN`, `DOCKER_NON_MINIMAL_BASE`, `DOCKER_ADD_FROM_URL` and `DOCKER_APT_NO_CLEAN`.
  `DOCKER_ADD_FROM_URL` does not fire when the `ADD` carries `--checksum`.
- Every Docker rule has a real-syntax bad and good example, and the uncovered lists of `docker__image` and `docker__instructions` are empty.

### Changed

- **Zones.**
  `dockerfile_expose` and `dockerfile_user` are private: a declared port is not internet exposure, and a `USER` line is not an administrative target.
  Exposure is decided by the Kubernetes, Compose or cloud definition that runs the image.
  `dockerfile_stage` is a private container.
- **Rule calibration.**
  Every Docker rule declares a `confidence` and the findings that share a cause share a `root_cause`.
  `DOCKER_NO_USER` drops from high to medium because it fires on something missing; `DOCKER_ROOT_USER` stays high.
  `DOCKER_ENV_SECRET` and `DOCKER_ARG_SECRET` drop from critical to high because they are inferred from a name.
  `DOCKER_NO_DIGEST_PIN` is low, `DOCKER_RUN_SUDO` is low, and `DOCKER_EXPOSED_SSH` now maps to T1021.004.
  `DOCKER_RUN_SUDO` maps to T1548.003.
  The rules with no honest attacker technique (`DOCKER_MISSING_WORKDIR`, `DOCKER_NON_MINIMAL_BASE`, `DOCKER_ADD_INSTEAD_OF_COPY`, `DOCKER_APT_NO_RECOMMENDS`, `DOCKER_APT_NO_CLEAN`, `DOCKER_COPY_NO_CHOWN`) no longer claim one.
  The hand-written `tactics:` are gone from every Docker rule and are derived from the techniques.
- The parser fills the fields of the parser-to-graph contract: `start_line` and `end_line` on every instruction and stage resource (`source_location` is the file path without a `:line` suffix), `declared=False` on every edge, and `diagnostics`.
  A value that cannot be resolved (a `FROM` tag, a `USER`, an `EXPOSE` port that depends on a variable with no default) is an `Unknown` instead of a guess.
  The `splitlines` line-number drift that the secret scanner audit item also names in `parsers/dockerfile.py` is gone with the new lexer.

### Removed

- `DOCKER_EXPOSED_PRIVILEGED_PORT` (recorded in `deprecated_ids`).
  Exposing port 80 or 443 is normal, and a container does not need root to bind a low port.
