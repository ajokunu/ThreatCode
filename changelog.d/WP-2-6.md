### Added

- **Effective launch resolution for MCP servers.**
  The parser now works out the command a client really runs before any check reads it.
  It unwraps `cmd /c` and `/k`, `powershell` and `pwsh -Command`, `bash`, `sh` and `zsh -c` strings, `env`, `sudo`, `nice`, `nohup`, `exec`, `command`, `timeout` and `wsl`, at most four layers deep.
  It resolves the package runners `npx`, `bunx`, `pnpm exec` and `dlx`, `yarn dlx`, `bun x`, `npm exec`, `uvx`, `uv tool run`, `uv run --with`, `pipx run` and `deno run npm:`, including version-pinned wrapper names.
  Pinning, secrets, filesystem exposure, container privileges and the shell-exec check all read this one result, so a wrapped launch is analysed like a direct one.
- **Bridge servers are remote servers.**
  `mcp-remote`, `supergateway` (`--sse` and `--streamableHttp`) and `mcp-proxy` lift their URL and their `--header`, `-H` and `--oauth2Bearer` values into the same remote, plaintext, authentication and secret checks as a native `url` entry.
  Such a server gets transport `stdio-bridge`, is in the internet zone, and records `bridge` and `bridge_allow_http`.
  `supergateway --stdio "<command>"` is read as the local command it wraps, not as a remote server.
- **A complete docker and podman option table.**
  The `docker run` options are split into value-taking and boolean sets generated from the Docker 29.8.0 CLI help, with podman additions.
  Global options before the subcommand (`--context`, `-H`, `--config`) and `docker container run` are handled, and the image is the first word after the options.
  An option that is in neither set is read as a boolean flag.
- **A new secret scorer** (`parsers/_mcp_secrets.py`, the only MCP module that imports the secret scanner).
  It scans `env`, `headers`, the URL (userinfo password, query parameters, and with medium confidence a long token in the path) and the launch arguments (`-e KEY=VALUE`, `--env`, `--flag=value`, `--flag value`, `--header 'Authorization: Bearer ...'`, bare `Bearer ...` strings).
  A value is a placeholder only when the whole value is a reference or template.
  `${VAR:-literal}` is expanded and the default is tested, and a literal next to a reference is tested as a literal.
  Key names are split on `_`, `-` and camelCase and need a whole token such as password, secret, token, apikey, bearer or pat, and keys ending in `_URL`, `_NAME`, `_TYPE`, `_ID`, `_PATH` and `_FILE` are not credentials.
  `PASSWORD=abc123` is now caught, and `TOKEN_URL`, `AUTH_TYPE`, `AWS_SECRET_NAME`, `OAUTH_CLIENT_ID`, `YOUR_API_KEY_HERE`, `your-token-here` and `%API_TOKEN%` are no longer reported.
- **Secret values never reach any output.**
  Only `kind:key` labels (`env:KEY`, `header:Authorization`, `url:userinfo`, `arg:--api-key`) and the argument indexes are stored.
  Secret-bearing arguments are redacted in place in `properties["args"]`: `KEY=[REDACTED]`, `--api-key=[REDACTED]`, `postgresql://user:[REDACTED]@host/db`, so the rest of the argument stays readable.
  Credentials in a package URL are replaced before they are stored.
- **A query credential or a URL userinfo counts as configured auth,** so `?api_key=literal` no longer also raises `MCP_REMOTE_NO_AUTH`.
  A server on a loopback address is not a remote server for that rule.
- **Pinning policy.**
  npm packages are pinned only by an exact semver, and git or `github:` sources only by a 40-character commit or a version tag.
  Ranges, partial versions and dist-tags are unpinned by policy, and so are branches and floating image tags (`latest`, `stable`, `main`, `edge`, `nightly`, `dev`, `develop`, `canary`, `beta`, `alpha`, `rolling`, `current`).
  Python packages are pinned only by `==` (or uv's `pkg@1.2.3`) or a commit or version tag.
  Images are pinned by digest or a version-shaped tag.
  Local targets (`./server`, `../x`, absolute paths, `file:`) are never reported.
  `properties["unpinned_reasons"]` says why each package is unpinned.
- **Filesystem and container exposure.**
  Path arguments are normalized first (`~`, `$HOME`, `${HOME}`, `${env:HOME}`, `${userHome}`, `%USERPROFILE%`, `$env:USERPROFILE`, backslashes, trailing slashes, `--allowed-directories=`).
  Broad paths (the filesystem root, drive roots, `/Users`, `/home`, `/mnt`, `/Volumes`, a home directory or its parent, `C:\Users`) and docker bind mounts of them set `broad_filesystem_access`.
  A custom-named filesystem server is found by its package words, and a named path flag counts on any server.
  Credential directories (`.ssh`, `.aws`, `.gnupg`, `.kube`, `.config`, `.azure`, `.docker`, the keychain folder) and system directories (`/etc`, `/var/run`, `/proc`, `/sys`, `/dev`, the docker socket) set the new `sensitive_filesystem_paths`.
  Container flags are parsed uniformly in the `--flag=value` and `--flag value` forms, so `--privileged=false` is not privileged.
  `--cap-add` uses the shared `DANGEROUS_CAPABILITIES` list (NET_ADMIN, NET_RAW, BPF and the rest), and `--device`, `--user root` or `0`, `--security-opt` with `seccomp=unconfined`, `apparmor=unconfined` or `no-new-privileges=false`, and bind mounts of `/etc`, `/var/run`, `/proc`, `/sys` and `/dev` are flagged.
  A missing `no-new-privileges` is only informational (`container_lacks_no_new_privileges`).
- **The agent capability model** (`parsers/_mcp_capabilities.py`).
  Each config scope gets one synthetic `mcp_agent` node (private compute) holding the union of what its enabled servers can do: `reads_private_data`, `ingests_untrusted_content` and `can_exfiltrate_or_act`.
  The tags come from one reviewed table of known packages and images, plus facts the entry itself proves (a shell server, a broad filesystem path, a remote server).
  A server that is not in the table adds nothing and is reported as `mcp.unknown_capability`.
  The graph gets an `iam_binding` edge `invokes` from the agent to each enabled server and a `data_flow` edge `returns_content` back, both marked as not declared and carrying `protocol` and `authenticated`.
- **New rule `MCP_LETHAL_TRIFECTA`** (high, heuristic, `mcp/agents.yml`) fires on an agent that has all three capabilities.
  It carries OWASP MCP Top 10 and Agentic Top 10 metadata and no ATLAS ids, because none has been checked against pinned ATLAS data.
- **New rule `MCP_SENSITIVE_PATHS`** (high, heuristic) for credential and system directories.
- **New rule `MCP_SECRET_LIKELY_IN_CONFIG`** (medium, heuristic) for a literal under a credential-like name that matches no known token format and does not look random.
  `MCP_SECRET_IN_CONFIG` (critical) now needs a known provider pattern, a random-looking value under a credential-like name, a literal in an Authorization-style header or a URL password.
- **Source lines for every server.**
  `start_line` comes from the JSON structure (scope and server key), so two servers with the same key in different scopes no longer share a line.
  Comments in JSONC files no longer shift the lines.
- **Diagnostics.**
  A server entry with none of `command`, `url`, `serverUrl` or `httpUrl` gets transport `unknown` and an `mcp.unknown_entry` warning.
  OpenCode (`mcp`) and Zed (`context_servers`) use other top-level keys, are not read, and are documented as unsupported.
  Gemini CLI `settings.json` is read: `httpUrl` is read like `url`.
- 20 new golden inputs: the 11 new fixtures under `tests/fixtures/mcp`, the 5 existing ones that had no recording, and the 4 real-shape MCP files.
- Real-shape and rule-case tests for every MCP rule, with `uncovered/mcp__servers.txt` and `uncovered/mcp__agents.txt` empty.

### Changed

- **Project-scoped servers in `~/.claude.json` use a hash of the full project path in the address.**
  The address is `mcp_server.<project basename>-<8 hex>.<server>` and the agent is `mcp_agent.<basename>-<8 hex>`, so `/work/a/app` and `/work/b/app` no longer collide and a literal token in one project is no longer dropped.
  The node `name` stays the server key, and the readable basename is in `properties["scope"]`.
  The old addresses (`mcp_server.shop.db`) are gone.
- **Disabled servers keep their node.**
  A server with `disabled: true`, `enabled: false` or a name in `disabledMcpServers` or `disabledMcpjsonServers` (top level or per project) has `properties["disabled"] = true`, no edges to the agent, and no findings from the exposure rules.
  The two secret rules still fire on a disabled server, because a credential stays in the file and in version control whether or not the server runs.
- **Loopback is decided by address, not by prefix.**
  Only `localhost`, names ending in `.localhost` and loopback IP literals (`127.0.0.0/8`, `::1`, IPv4-mapped forms) are loopback.
  `http://127.attacker.com` and `http://127.0.0.1.nip.io` are remote and plaintext.
- **Shell-exec detection reads the package, not every argument.**
  It looks at the package position of the effective launch (the package or `--from` value, the `python -m` module, the image repository), so `node /Users/me/projects/mcp-shell-docs/server.js` is no longer a shell server.
  `iterm-mcp`, `ssh-mcp` and `mcp-server-ssh` are added to the known list.
- `strip_jsonc` removes a trailing comma only outside strings, so `"abc,}"` keeps its comma, and it keeps the newlines of block comments.
- All MCP rules are calibrated with a declared confidence (definitive, heuristic or absence), and the exposure rules skip disabled servers.
  `MCP_UNPINNED_PACKAGE` states that a semver range counts as unpinned by policy.
  The MITRE tactics of every MCP rule equal the tactics derived from its techniques, so `MCP_PLAINTEXT_TRANSPORT` gains TA0007 (from T1040).
- A resource's `source_location` is the file path without a `:line` suffix, and the line is in `start_line`.
- The scanned MCP configs now include the `mcp_agent` node in the resource count.

### Golden differences

Every difference is inside `tests/fixtures/golden/mcp__*` and `tests/fixtures/golden/real_shapes__mcp__*`.

- `mcp__fixed__.mcp.json`: `graph.json` gains the `mcp_agent.config` node and ten edges (an `iam_binding` and a `data_flow` per server), and `model.json` is new.
  There is still no rule finding.
  The model holds two boundary threats, one for each direction of the edge pair that crosses to the remote `inventory` server.
- `mcp__vulnerable__.mcp.json`: `graph.json` gains the agent node and ten edges.
  `findings/mcp__servers.json` gains `MCP_SENSITIVE_PATHS` on `builder`, because its bind mount of `/var/run/docker.sock` is a sensitive path.
  `model.json` is new with the same two boundary threats for the remote `inventory` server.
- The other 20 recordings are new inputs.
  Their rule findings are the ones the new fixtures were written to show: launcher forms, secret forms and false positives, filesystem and container exposure, disabled servers, the project hash, the trifecta and its negatives, unknown shapes and the Gemini `httpUrl`.
  The real-shape desktop config fires `MCP_LETHAL_TRIFECTA` because the `github-mcp-server` image reads private repositories, ingests issues written by others and can comment.
