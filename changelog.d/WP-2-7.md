### Added
- **Enrichment layer** (`ir/enrich.py`, `ir/enrichment/`).
  After the graph is built, `enrich` computes the facts a rule needs and writes them under `node.properties["derived"]`.
  `derived.*` is the new convention for rule conditions, and the namespace is reserved: an input that carries its own `derived` attribute has it replaced, so it cannot forge a fact.
  Every module in `threatcode.ir.enrichment` is loaded in sorted order and may export `COMPANIONS`, `DERIVERS`, `RELATIONS` and `DEFAULTS`.
  The work runs in phases across all modules (defaults, companions, derivers, relations), so a provider rule package adds a module and never edits the core ones.
  No built-in rule reads `derived.*` yet, so findings are unchanged until the provider rule packages switch to it.
- **Companion folding.**
  A resource that configures another is folded into its parent through the attribute that points at it.
  S3 buckets get `versioning_enabled`, `sse_algorithm`, `logging_enabled`, `public_access_block`, `acl`, `object_ownership` and `policy_statements` from the provider v4 split resources, with the provider v3 inline blocks merged in.
  VPCs get `has_flow_log`, secrets get `rotation_enabled`, WAF web ACLs get `has_logging_config` and `associated_resource_arns`, and every `azurerm_*` resource gets `has_diagnostic_settings`.
  `azurerm_mssql_server` gets `auditing_enabled` and `alert_policy_enabled`.
  Cloud Run services and Cloud Functions get `invoker_members`, and BigQuery datasets get `access_members`.
  IAM roles get `attached_policy_arns`, `attached_policy_statements`, `inline_policy_statements` and `assume_role_statements`.
  Security groups get `ingress` and `egress` in one canonical shape, folded from the inline blocks, `aws_security_group_rule` and the `aws_vpc_security_group_*_rule` resources.
- **Link resolution that never guesses.**
  A companion finds its parent by reference first (`${aws_s3_bucket.b.id}`, a counted instance, a CloudFormation intrinsic, or the reference an `Unknown` carries), then by a literal id, name or ARN that exactly one parent has.
  A plain word is never matched to a resource label.
  A companion whose link cannot be resolved (a variable, a value known only after apply, an ambiguous name) makes the same keys `Unknown` on every candidate parent instead of leaving them looking unconfigured.
  A companion that names something outside the scan, or a node of another type, is ignored.
  A known `True` still wins over an `Unknown`, and an `Unknown` wins over `False`.
- **Role relations.**
  Lambda functions, ECS task definitions, instances (through their instance profile), SageMaker notebook instances and EKS node groups get `role_attached_policy_arns`, `role_policy_statements` and `role_ids` from the role they run as.
  A role the scan cannot see makes them `Unknown`, never empty, and a compute resource with no role attribute gets none of them.
- **Policy documents** (`ir/policy.py`).
  `normalize_policy` reads a mapping, a JSON string in any whitespace, python-hcl2's escaped and doubly escaped quotes, and the `${jsonencode(...)}` Python repr into `Statement` objects (effect, actions, not_actions, resources, not_resources, principals, has_condition, condition_keys).
  It never evaluates anything and returns `Unknown` for what it cannot read, including a policy from a data source.
  The result is written as plain dicts to `derived.policy_statements`, `derived.assume_role_statements` and `derived.inline_policy_statements` for IAM, KMS, S3, SQS and SNS policies.
  ECS `container_definitions` and SQS `redrive_policy` are parsed into `derived.container_definitions` and `derived.redrive_policy`.
  The original attributes are left as written.
- **Provider defaults mechanism.**
  A module's `DEFAULTS` table fills an absent attribute in place on Terraform HCL and CloudFormation config nodes, never on plan JSON or design evidence, and lists the filled paths in `derived.defaults_applied`.
  A nested path such as `vpc_config.endpoint_public_access` is filled only when the block exists.
  The shipped registry is empty, so nothing is filled yet.
  The node's format is read from `graph.node_formats`, which the graph builder does not populate yet, so the mechanism stays inert until it does.

### Changed
- Rule threats now carry `location_file`, `location_start_line` and `location_end_line` from their node, so they appear in JSON output when the parser knows them.
  Threat ids do not depend on the location.
- `scanned_resources` no longer counts looked-up data sources.
- The engine indexes rules once by exact resource type, with the glob rules in a short separate list, instead of testing every rule against every node.
  Findings and their order are identical.
- No golden recording changed.
