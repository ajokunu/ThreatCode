### Added
- **One scan command for files, directories and standard input.**
  `threatcode scan PATH...` takes any number of files and directories, and `-` reads standard input.
  `--stdin-name main.tf` (or `Dockerfile`, or `plan.json`) tells the scan which parser to use for piped text.
  Without a name, input that starts with `{` or `[` is read as JSON and anything else as YAML, so `terraform show -json tfplan | threatcode scan -` works as it is.
  Everything the scan finds goes into one graph.
- **A directory is understood the way the tools that wrote it understand it.**
  A directory with `.tf`, `.tofu` or `.tf.json` files is one Terraform module, so a subnet in `network.tf` and an instance in `main.tf` share a graph.
  A Terraform plan JSON in the same directory replaces the module, because the plan holds the resolved values, and the scan records an info diagnostic saying so.
  Every `Chart.yaml` is one Helm unit that owns its `templates/` and `charts/` folders and its values files.
  Any other `.json`, `.yml`, `.yaml`, `.template`, `.cfn`, Dockerfile-family or MCP config file is its own unit.
  When two units declare the same address, each one is prefixed with its path, such as `infra/net::aws_vpc.main`, in the same order on every run.
- **A walker for repositories you did not write.**
  It reads only regular files.
  Symlinks inside the tree are skipped and counted, which also ends link cycles and stops a link from pulling in a file outside the scan root.
  A symlink you name on the command line is followed.
  Named pipes, sockets and devices are skipped and counted, so a pipe called `main.tf` cannot hang the scan.
  `.git`, `node_modules`, `.terraform`, `vendor`, virtualenvs, build output, tool caches and every dot-directory except `.cursor` and `.vscode` are not entered.
  A JSON or YAML file over 50 MB is set aside as not infrastructure.
- **Exit codes 0, 1 and 2, with 2 meaning the scan could not be trusted.**
  Exit 2 covers an unreadable path, a file a parser claimed but could not parse, a scan with nothing to model, an ingest file that is unreadable or unrecognized, a bad option, and `--strict` with any coverage gap.
  Exit 1 means a finding or attack path at or above `--fail-on` survived suppressions and the baseline.
  Exit 0 is everything else.
  When more than one applies, 2 wins over 1 and 1 wins over 0.
  Findings from the LLM are advisory and never set exit 1.
  A run with `--write-baseline` exits 0 unless an input error occurred.
- **`--fail-on`, and a `--min-severity` that only changes what you see.**
  `--fail-on` takes `critical`, `high`, `medium`, `low`, `info` or `none` and gates on the effective severity of a finding when it has one, otherwise on its base severity.
  `--min-severity` hides findings below it from the listing and from every output format.
  The gate is computed before that filter, so `--min-severity critical --fail-on high` shows only critical findings and still exits 1 on a high one.
- **A `coverage` block in every report.**
  It lists the files discovered, the units parsed, the files that are not infrastructure (a count and the first 20 paths), symlinks and special files skipped, input errors with the file, a code and the message, coverage gaps, failed rule evaluations, and how many findings were suppressed or baselined.
  Gaps are the warning diagnostics the parsers and the graph record, such as an unanalysed module call, a Helm fallback render, unknown plan values, an unresolved intrinsic or a skipped document.
  `--strict` turns any gap into exit 2.
- **Errors and gaps always reach stderr.**
  `--quiet` hides progress, notices and the written-to message.
  It does not hide input errors, coverage gaps, failed rules or a failed LLM run.
- **A text report for terminals.**
  `-f text` prints the severity counts, one line per finding with its resource, rule, title and location, the attack paths, and a coverage summary.
  It is the default when stdout is a terminal and no `-o` is given.
  Colors appear only on a terminal, and `NO_COLOR` or `--no-color` turns them off.
- **Fingerprints on every finding.**
  A fingerprint is 16 hex characters of a SHA-256 over the kind of finding, its rule id (or boundary key), its resource address and its root-relative source file.
  Property values are left out, so editing a resource does not change which finding it is.
  A finding can carry `metadata['fingerprint_hint']` to replace the address part.
  Threat ids are unchanged.
- **Suppressions that work before the gate.**
  `.threatcodeignore` is read from the scan root, or from `--ignore-file`, and `--no-ignore` turns it off.
  An entry matches a rule id, a threat id, a fingerprint or any alias such as a CVE or GHSA id, ignoring case.
  `exp:YYYY-MM-DD` ends an entry, and a malformed date counts as already expired and is warned.
  `reason:"text"` is read and kept.
  Entries that matched nothing and entries that expired are reported once, and the file used and the number suppressed are printed.
  An entry with an option this version does not know is skipped with a warning.
- **Baselines.**
  `--write-baseline FILE` records one sorted entry per finding (`fingerprint`, `rule_id`, `resource`, `severity`) under the schema `threatcode-baseline/1`.
  `--baseline FILE` removes those findings from the gate and the listings and counts them in `coverage.baselined`.
  A baseline is not written when the scan had input errors, because it would hide the findings of the files that failed.
- **Reproducible output.**
  `SOURCE_DATE_EPOCH` fixes the report timestamp and `--no-timestamp` leaves it out.
  Findings are sorted by effective severity, resource address, rule id and id.
  Every path in a report is POSIX and relative to the scan root, the common parent directory of the named paths (the current directory for standard input), so the same tree gives byte-identical output wherever it is checked out.
- **One settings resolver.**
  A flag wins over `THREATCODE_FAIL_ON`, `THREATCODE_MIN_SEVERITY`, `THREATCODE_FORMAT` and `THREATCODE_LLM`, which win over the config file, which wins over the defaults.
  Click options that carry a default of their own now default to `None`, so a config file's `min_severity` and `output_format` finally take effect when the flag is absent.
  The config models reject unknown keys and name the key, with a suggestion for a typo and a pointer for a removed key.
  A config file that is not a mapping is a clear error instead of a traceback.
  `max_nodes`, `max_edges` and `strict_edges` can be set in an explicit config, and `--max-nodes` and `--max-edges` set the limits for one run.
- **A config file in the scanned repository cannot widen its own trust.**
  An auto-discovered `.threatcode.yml` (in the scan root or the current directory) is announced on stderr with the fields it set.
  Only `min_severity`, `output_format` and `redaction` are read from it.
  `fail_on`, `extra_rule_paths`, `llm` and the graph limits are ignored with a warning, so a pull request cannot turn off its own gate.
- **Group options and help.**
  `-v` (repeatable), `-q`, `--debug`, `--no-color` and `--version` go before the command.
  Every help text ends with examples and the exit codes, and the group and scan help add the environment variables.
  A ThreatCode error prints `Error: <message>` and exits 2, and an unexpected exception prints one line and exits 2.
  The traceback appears only with `--debug` or `THREATCODE_DEBUG=1`.
- **`diff` checks what it is given.**
  Both files must be JSON reports from `threatcode scan -f json`, and SARIF and other JSON get their own messages instead of reading as "no changes".
  Ids are compared as multisets, so a threat that appears twice counts twice.
  A threat with the same id and a different severity or title is reported as changed.
  Output is sorted by severity, `-f text` is new, `-o` is supported, and `--fail-on-new SEVERITY` exits 1 when a threat at or above it was added or got worse.
- **A Python API that goes through the same pipeline.**
  `scan(paths, **settings)` returns the report dict, `analyze(paths, **settings)` returns the graph with the report, and `run_scan(ScanRequest)` returns the full `ScanResult` with the exit code and the coverage.
  `__all__` lists these with `ScanRequest`, `ScanResult`, `AnalysisResult`, `ThreatReport`, `Threat`, `Severity` and the exception classes, which now include `UsageError`.
  The names load on first use, so `import threatcode` stays cheap.
  `scan` and `analyze` raise `ThreatCodeError` when an input could not be analysed, so a caller cannot take a partial result for a clean one.
  `run_scan` returns the partial result.
- **Seams for the ingestion and secrets packages.**
  `threatcode.ingest.load_and_attach(paths, graph, root)` and `threatcode.engine.secrets.iac.find_secrets(units, graph)` are called by the pipeline with their final signatures.
  `--ingest` refuses every file until ingestion lands, and the refusal names the file.

### Changed
- **Breaking: the default `--fail-on` is `high`.**
  Before, any finding made `scan` exit 1.
  A scan whose worst finding is medium or lower now exits 0.
  `--fail-on info` restores the old behavior, and `--fail-on none` never fails on findings.
- **Breaking: errors exit 2, not 1.**
  A parse failure, an unreadable file, a bad config and a missing output path used to exit 1, the same as a finding.
  Scripts that test for exactly 1 to mean "findings" now get that meaning back.
- **Breaking: the LLM is opt-in.**
  A model is contacted only with `--llm`, `THREATCODE_LLM=1`, or `llm.enabled: true` in a config named with `--config`, and `--dry-run` builds the request without sending it.
  An exported `ANTHROPIC_API_KEY` no longer sends the redacted graph anywhere by itself.
  `--no-llm` still works and wins over the config.
  `--dry-run` with `--no-llm` is a usage error.
  The "no API key" warning appears only when `--llm` was asked for.
  The factory that builds the client moved to `threatcode.engine.llm.factory.build_client(settings)`, and `llm.temperature` is now passed to the client.
- **Breaking: the report always carries `schema_version`, `attack_paths` and `coverage`.**
  `ThreatReport.to_dict` writes them even when they are empty.
  `timestamp` is omitted when `--no-timestamp` is given.
  The summary counts and the severity filter use the effective severity when a finding has one.
- **Breaking: paths in output are relative to the scan root.**
  `input_file` and `location_file` are POSIX paths relative to the common parent of the named paths, and `input_file` is `.` for a directory.
  Findings take their location from the resource they sit on.
- **Breaking: Python API.**
  `scan(input_path, no_llm=..., output_format=..., ...)` became `scan(paths, **settings)`.
  The `output_format` parameter was accepted and ignored, so passing it is now a `TypeError`; `threatcode.formatters.render(name, analysis)` renders other formats.
  `no_llm` is gone because the LLM is off unless `llm=True`.
- **Breaking: config keys.**
  `no_llm` and `dry_run` were never read and are removed, and a file that still has them fails with a message that says what replaces them.
  `output_format` accepts the names in the format registry, which no longer includes `cyclonedx`.
  `min_severity`, `output_format` and the new `fail_on` have no default in the model so that "not set" can be told from a value.
- **`-o` writes the report and says so on stderr.**
  `Report written to <absolute path>` goes to stderr, so stdout stays empty.
  A directory, or a path that cannot be written, is `Error: cannot write <absolute path>: <reason>` with exit 2 and no traceback.
- **A scan that parsed nothing no longer prints a "0 findings" summary.**
  The error lines and the incomplete-scan line are printed instead.
- **Terraform state JSON and destroy-only plans** are reported with the command that fixes them, now as input errors with exit 2.

### Removed
- **`threatcode.ignore`.**
  `load_ignore_ids` and `apply_ignore` are replaced by `threatcode.suppressions` (`load`, `apply`, `write_baseline`, `load_baseline`, `apply_baseline`).

### Fixed
- A parse failure no longer produces a report that looks clean.
  The failing file is named in `coverage.errors` and on stderr and the scan exits 2.
- A scan of a directory of Kubernetes, CloudFormation or Docker files no longer fails with a message about Terraform; every supported file in the tree is scanned.
- Ignoring every finding now exits 0, because the gate is computed after suppression.
- A config file that is a YAML list no longer ends in an `AttributeError` traceback.
- A config's `min_severity` and `output_format` were overwritten by the command-line defaults and never took effect.
- A file that is not text, an empty file and a file nothing recognizes each get one message that names the file.

### Carried over from earlier waves
- `report.rule_errors` is counted once on stderr and in `coverage.rule_errors`, and the LLM status is printed when the LLM phase failed.
- The graph limits (`max_nodes`, `max_edges`) and `strict_edges` reach `InfraGraph` from the config and the command line.
- `cyclonedx` is gone from the `output_format` values.
- `run_scan` passes root-relative source paths to `InfraGraph.from_units`, so qualified ids never contain an absolute path.

### Recording differences
None.
The golden recordings use the library path and are unchanged, and `tests/test_ir/test_golden.py` passes without a re-record.
