### Added
- **Exposure on every node.**
  `InfraNode.exposure` is now decided: `internet` for a node the configuration puts within reach of the internet, `internal` for a node that is known to be kept off it, and `unknown` for everything else.
  The signals are an internet-facing load balancer (CloudFormation `Scheme: internet-facing` included), a Lambda function URL without authorization, an API Gateway REST API with an EDGE or REGIONAL endpoint (a PRIVATE one is internal), an HTTP API, a CloudFront distribution, a database with `publicly_accessible` true, an S3 bucket whose ACL is `public-read` or `public-read-write` or whose policy allows `*` without a condition and is not blocked by its public access block, a security group with world-open ingress, an Azure rule that is Inbound, Allow and from a world source, a GCP firewall that allows ingress from a world range, an EKS cluster with a public endpoint, an AKS cluster that is not private, an Azure service with public network access, and a Kubernetes LoadBalancer or NodePort Service or an Ingress with rules.
  A subnet is public when its route table sends `0.0.0.0/0` or `::/0` to an internet gateway or when `map_public_ip_on_launch` is true, and an internet gateway attached to a VPC does not make a private subnet public.
  An instance or launch template with a public IP or an Elastic IP, in a public subnet, behind an exposed security group is exposed and in the DMZ.
  A listener takes the exposure of its load balancer.
  A data store never leaves the DATA zone: a public database or bucket keeps its zone and gains `exposure: internet`.
- **Provider defaults for exposure are documented.**
  A template or an HCL file leaves out values a plan materialises, so exposure reads EKS `endpoint_public_access` true, AKS `private_cluster_enabled` false, `public_network_access_enabled` true for the Azure services in `PUBLIC_NETWORK_TYPES`, and `azurerm_storage_account` `allow_nested_items_to_be_public` true when the attribute is absent.
  They apply only to Terraform HCL and CloudFormation config input, never to a plan or a design input, and they are the values the provider rule packages put in their `DEFAULTS` tables.
- **Tri-state exposure flags.**
  `tri_state(value, evidence)` reads a flag as `true`, `false` or `unknown`.
  Only `true` selects the DMZ.
  An `Unknown`, `"${var.public}"`, `"var.public"`, a CloudFormation intrinsic and the string `"false"` no longer count as public, and a design node whose flag is missing is unknown, not false.
- **New categories `secret` and `api`.**
  KMS keys, Secrets Manager secrets, SSM parameters, ACM certificates, API Gateway API keys, Azure Key Vault, Google KMS and Secret Manager, and Kubernetes Secrets are `secret` (a data store, zone DATA).
  API Gateway REST and HTTP APIs, Lambda function URLs and Azure API Management are `api`.
  `NodeCategory` gains `SECRET` and `API`, and the JSON `category` field can now carry either value.
- **Many more types have a category.**
  RDS and Aurora, Redshift, EFS, OpenSearch and Elasticsearch, DocumentDB, Neptune, MSK, Kinesis, ECR, SageMaker, Cognito, WAFv2, NAT and VPN gateways, transit gateways, load balancer target groups and listeners, route tables, VPC endpoints, CloudTrail, Config, GuardDuty and flow logs on AWS; mssql, postgresql, mysql, cosmosdb, storage, redis, key vault, public IP, application gateway, front door, load balancer, web apps, container registry, monitor and role assignment on Azure; Cloud SQL, BigQuery, Spanner, Redis, Cloud Run, forwarding rules, backend services, KMS and Pub/Sub on GCP.
  `tests/test_ir/test_catalog_cloud.py` fails when a built-in rule targets a resource type with no category, and when a data store type is outside the DATA zone.
- **IAM edges (`ir/iam.py`).**
  A role is found by the reference, then the `name` attribute, then an ARN, then the resource label.
  An attachment names its policy (`iam_binding`, `attaches`), a role holds the policies attached to it and its inline policies (`has_policy`), a trust policy makes a principal role able to assume the role (`can_assume`, from the principal to the role) while service principals, account roots and `*` stay metadata in `derived.assume_role_trust`, a bucket, queue, topic or secret policy links to its resource (`resource_policy`, with `public`), and an Allow statement links the role to the resources it covers (`permission`, with `actions`, `access` of `read`, `write` or `admin`, `wildcard` and `conditional`).
  A wildcard resource or an ARN pattern fans out to the nodes of the services the actions name, data stores first, capped at 25 per role, with one `graph.iam_fanout_capped` information diagnostic when the cap is reached.
  Deny, `NotAction` and `NotResource` statements are not read.
- **Public graph API.**
  `InfraGraph.to_export_dict(include_properties=False)` returns the nodes (id, type, name, category, zone, exposure, boundary, evidence, stride element, module, mode, source file and lines) and the edges (type, relation, declared, crossing, zones, attributes) in a stable order.
  `subgraph(edge_types)` returns a `MultiDiGraph` that keeps parallel edges, `reachability_subgraph()` returns the network flow, data flow and IAM binding edges, `add_edge()` adds an inferred edge from a later pass, and `get_neighbors` takes a `direction` (`out`, the default, `in` or `both`).
  `InfraGraph.node_formats` maps each node to the format of its parser and `zone_declared` lists the nodes whose zone the input declared.
  `ir.edges.FLOW_EDGE_TYPES` is the set of traffic-carrying edge types.
- **New literal resolution.**
  `ReferenceIndex.resolve_literal` finds the node of a required type by its `id`, `arn` or `name` attribute, by the last component of an ARN, then by address or label.
  `resolve_value` reads an `Unknown`, an interpolation, an intrinsic or a list the same way, and `parse_arn` splits an ARN.
- New diagnostic code `graph.iam_fanout_capped`.

### Changed
- **Breaking: edges exist only because the input names their target.**
  The "first node of a type" containment heuristic and the matching of subnets, security groups and roles on `node.name` are gone.
  A reference, a dependency, or a literal that resolves through the reference index (an address, an id, an ARN, a name attribute, the resource label as the last resort) makes an edge.
  A literal that names nothing makes none, except that a literal `vpc_id` (or a registered containment hint) binds the only VPC of its input, and that edge carries `binding: only_candidate`.
  With several candidates the build adds no edge and reports `graph.ambiguous_reference`: a warning when the value matches several nodes, information when it matches none of them.
  A plan with `aws_vpc.prod` and `aws_vpc.dev` and a subnet whose `vpc_id` is a literal id no longer attaches the subnet to `aws_vpc.prod`.
  `multi_service_insecure.plan.json` and `multi_service_secure.plan.json` have two VPCs and the literal `vpc-12345`, so their 12 subnet, security group, route table and internet gateway containment edges to the first VPC are gone and their `depends_on` dependency edges remain.
- **Breaking: security group attachment is a dependency edge with relation `security_group` for every input.**
  The literal-value path used to make it a `network_flow` edge, which is reserved for traffic.
- **Placement edges for Azure and Google.**
  `virtual_network_name`, `virtual_network_subnet_id` and `ip_configuration[].subnet_id` on Azure, and `network` and `subnetwork` on Google, are containment edges to the network or subnet they name (they were generic `references` dependency edges).
  The dead `vnet_id` and `network_id` hints are removed.
  `register_containment_hint` joins the same attachment table and is source-compatible.
- **Breaking: zones follow the category.**
  The lookup order is a property override, then an explicit prefix entry, then the default zone of the category: DATABASE, STORAGE and SECRET are DATA, IAM and MONITORING are MANAGEMENT, CDN is DMZ and everything else is PRIVATE.
  `aws_db_instance` and the other RDS, Azure SQL, Cosmos, storage account, Key Vault and Cloud SQL types were PRIVATE and are DATA, KMS keys and secrets are DATA, CloudTrail and flow logs are MANAGEMENT, API Gateway, Cognito, WAFv2 and NAT gateways are DMZ.
  `aws_db_subnet_group`, parameter and option groups and their ElastiCache, Redshift and DocumentDB relatives are NETWORK and PRIVATE under both Terraform and CloudFormation names.
  Dockerfile, lockfile and MCP types keep PRIVATE whatever their category.
  `infer_trust_zone(resource_type, properties, category=None, evidence="config")` stays positional-compatible.
- **Breaking: a public data store stays in the DATA zone.**
  `publicly_accessible` true used to move a database to the DMZ, which made it an attack path entry that could never be a target.
  It now keeps zone DATA and gets `exposure: internet`.
  A load balancer with `internal` true is PRIVATE, an API Gateway REST API whose only endpoint type is PRIVATE is PRIVATE, a Lambda function URL with authorization `NONE` is DMZ, an Azure rule is DMZ only when it is Inbound, Allow and from a world source, and a GCP forwarding rule with an INTERNAL scheme is PRIVATE.
- **Breaking: boundary threats come from traffic.**
  A boundary threat needs a `network_flow` or `data_flow` edge (declared design flows included) between two nodes that can exchange traffic.
  Containment, dependency and IAM edges no longer produce one, and neither does a flow to or from a VPC, a subnet, a namespace, a security group, a network ACL, a route table or a policy.
  Across the 96 recorded inputs the count falls from 273 to 27; every one that remains is a Kubernetes Service or Ingress flow (6), the flow of an MCP server into its agent (17) or a SAM API Gateway flow into its function (4).
  A Terraform plan or HCL input has none until reachability edges land.
- **Boundary threats are one per pair, with unique ids.**
  All flow edges between one source and target merge into one threat, and the id hashes the pair and the sorted edge types, so two edge types between one pair no longer repeat an id (realistic fixture 01 had two ids that appeared twice).
  The title names both endpoints and zones (`Trust boundary crossing: aws_lb.front (dmz) -> aws_instance.app (private)`), `target_address` is set, and the description says what is known about the flow instead of one fixed sentence.
  The metadata holds `boundary_key`, the addresses and zones, and `flow` (edge types, relations, protocols, ports, authenticated, encrypted).
- **Boundary STRIDE, ATT&CK and severity follow the flow.**
  A flow declared unauthenticated is spoofing (T1557), one declared unencrypted (or on `http`) is information disclosure (T1040), and any other is tampering (T1565.002).
  Internet to DMZ adds T1190, into the data zone T1530 and into the management zone T1078, and the tactics are derived from the techniques.
  The severity comes from the zone pair, treats a source with `exposure: internet` as the internet, and is one level lower when every merged edge declares the flow encrypted and authenticated.
  A flow about which nothing is known has confidence 0.5.
- The node limit error and the edge cap warning name the `--max-nodes` and `--max-edges` flags and the `max_nodes` and `max_edges` configuration keys as well as the environment variables.
- The `crosses_trust_boundary` flag is still set on every edge whose zones differ, so a diagram can draw it; only the threat generation filters.

### Fixed
- A subnet or security group whose literal `vpc_id` named the second VPC of an input was attached to the first VPC.
- A role attachment whose `role` is the role's `name` attribute (`atlas-ml-sagemaker-execution-role`) found no role, so no IAM edge existed on any realistic input.
- `InfraGraph` never recorded the format of its nodes, so the provider defaults that enrichment applies to HCL and CloudFormation (it reads `graph.node_formats`) could not apply to a real scan.
- An internal load balancer and its listeners were in the DMZ.

### Golden recordings
Only `graph.json` and `model.json` changed (84 files, in 53 of the 96 recorded inputs); no `findings` or `secrets` file did.
Each row counts the nodes whose zone changed, whose category changed, and that gained an exposure, the edges added and removed, and the boundary threats before and after.
Every zone and category change is a data store, secret store, monitoring service or API now catalogued; every exposure is one of the signals above; every removed edge is a security group attachment that is now a dependency edge, a containment edge now typed correctly, or the first-VPC edges named above; every added edge is an IAM edge, a nested `vpc_config` or network interface placement the old heuristic missed, or a retyped placement.
