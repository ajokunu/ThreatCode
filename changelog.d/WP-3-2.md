## AWS network and compute rules that read real shapes (WP-3-2)

The twelve rule files `vpc`, `ec2`, `elb`, `cloudfront`, `waf`, `wafv2`, `eks`, `ecs`, `lambda`, `api_gateway`, `ecr` and `sagemaker` are rewritten against the shapes Terraform HCL, `terraform show -json` and CloudFormation really produce.
Rule IDs stay stable wherever a rule survives, so existing `.threatcodeignore` lines keep working.
The 40 rules of these files became 50: 15 new, 5 deleted.
The severity distribution of the files moved from 1 critical, 13 high, 22 medium and 4 low to 0 critical, 7 high, 21 medium and 22 low.
Every rule now declares its confidence (21 definitive, 8 heuristic, 21 absence), and a test keeps absence rules at medium or below and heuristic rules at high or below.

### Fixed

- **Security group rules fire on real ingress.**
  `SG_UNRESTRICTED_INGRESS` searched the ingress list for the string `0.0.0.0/0`, which a list of objects can never contain, so it fired on nothing real.
  It now reads `derived.ingress`, the one list that folds inline `ingress` blocks, `aws_security_group_rule` and `aws_vpc_security_group_ingress_rule` into the same shape, and fires when an item allows `0.0.0.0/0` or `::/0` to every port (protocol `-1`), or to a port range that overlaps an administration or database port.
  The ports are `threatcode.vocab.ADMIN_PORTS` and `DATABASE_PORTS` written out in the rule, and a test keeps both lists equal.
  The same group in HCL, plan JSON and CloudFormation gets the same rules, which a table of 13 configurations checks.
- **A public load balancer group is no longer high.**
  World-open 80 and 443 move to the new `SG_WEB_PORT_OPEN_TO_WORLD` at low severity, so an ALB security group is a note and an open SSH rule is a high finding.
  A rule that opens everything, or a range that covers 22, is reported by `SG_UNRESTRICTED_INGRESS` only.
- **`VPC_DEFAULT_SG_OPEN` stops firing on a locked-down group.**
  It reports an ingress or egress item only when it allows a CIDR block, a prefix list or another security group; a rule that lets members reach each other (`self = true`) is silent.
- **`VPC_NO_FLOW_LOGS` reads real flow logs.**
  It used to test a tag called `flow_logs_enabled`, so it fired on every VPC and ignored `aws_flow_log`.
  It now reads `derived.has_flow_log`: a flow log of the VPC silences it, a flow log of another VPC does not, a flow log whose VPC cannot be resolved leaves it out, and the old tag counts for nothing.
  A flow log on a subnet of the VPC counts as partial coverage and silences it too; a flow log whose subnet cannot be tied to a VPC makes every VPC undecided.
- **The WAF rules read the `rule` attribute.**
  `WAF_NO_RATE_LIMITING`, `WAF_NO_MANAGED_RULES` and the five `WAFV2_*` rules read properties no parser ever produced (`has_rate_based_rule`, `has_sqli_rule` and others), so they were dead or fired on everything.
  A new enrichment walks the `rule` blocks, through `and`, `or` and `not` statements, rate-based scope-down statements and the rule groups a web ACL references, and writes `has_rate_based_rule`, `rate_limit` (the lowest limit), `managed_rule_groups`, `has_managed_rules`, `has_sqli_rule`, `has_xss_rule`, `has_ip_reputation` and `has_geo_match` under `derived`.
  A plan lists every statement type with most of them empty, and the empty ones do not count.
  A fact is unknown, never false, when the rule list cannot be read (`rule_json`, an unresolved dynamic block) or the web ACL references a rule group the scan does not hold.
  `WAF_NO_LOGGING` reads `derived.has_logging_config` from the logging configuration resource, and `WAF_EMPTY_RULES` reads `derived.has_rules`, which looks at `rule`, not `rules`.
  The rule list of a CloudFormation rule group is `Rules`, which the template translator renames for web ACLs only, so the enrichment reads both spellings.
- **`EKS_OUTDATED_VERSION` compares against a list.**
  It fired on every cluster that left `version` unset, which is the opposite of an old version.
  It now matches a documented list of the Kubernetes versions whose extended support in Amazon EKS has ended (1.10 to 1.30), checked on 2026-10-07 against the EKS release calendar, where 1.31 is the oldest version still in extended support until 2026-11-26.
  An unset or unresolved version is not a finding.
- **EKS public endpoint.**
  `EKS_PUBLIC_ENDPOINT` treats an omitted `endpoint_public_access` as the provider default, true, so an HCL or CloudFormation cluster that says nothing is reported, and a plan that states `false` is not.
- **ECS container rules read parsed definitions.**
  `ECS_PRIVILEGED_CONTAINER`, `ECS_NO_READONLY_FS` and `ECS_NO_LOGGING` searched the JSON text for `"privileged":true` and similar, which a pretty-printed definition never contains.
  They now use `any_item` over `derived.container_definitions`.
  An omitted `readonlyRootFilesystem` counts as writable, because that is the ECS default.
- **`LAMBDA_OVERPERMISSIVE_ROLE` reads permissions, not names.**
  It searched the role ARN for the word `admin`.
  It now fires when the execution role has `AdministratorAccess`, `PowerUserAccess` or `IAMFullAccess` attached (also in the GovCloud and China partitions), or a policy that allows every action or `iam:*` on every resource.
  A role named `admin-readonly` with a read-only policy is silent, and an admin policy attached to a role named `exec` is found.
  A role outside the scan (a variable, a module output, an ARN of another stack) leaves the finding out instead of guessing from its name.
- **`LAMBDA_NO_VPC` is an isolation note.**
  It is low severity, heuristic, `information_disclosure` instead of `elevation_of_privilege`, and it no longer claims ATT&CK `T1190`.
- **`ELB_NO_HTTPS` accepts the recommended pattern.**
  An HTTP listener whose default action redirects to HTTPS is silent; one that forwards, or redirects to HTTP, is reported.
  `ELB_NO_ACCESS_LOGS` requires `access_logs.enabled = true`, because a block that only names a bucket leaves logging off.
  `ELB_OUTDATED_TLS` lists the six policies that still negotiate TLS 1.0 or 1.1.
- **`CLOUDFRONT_NO_GEO_RESTRICTION`** reads `restrictions.geo_restriction.restriction_type` equal to `none`; it tested `restrictions` for absence, a required block.
  `CLOUDFRONT_NO_HTTPS` also reads the ordered cache behaviors and no longer fires on a missing required block.
  `CLOUDFRONT_NO_WAF` never fires on a `web_acl_id` the scan cannot resolve.
- **`EC2_PUBLIC_IP`** no longer tells a bastion host to use a bastion host; the mitigation suggests Session Manager or a restricted security group.

### Added

- **`EC2_IMDSV1`** (medium, heuristic, ATT&CK `T1552.005`) for `aws_instance`, `aws_launch_template` and `aws_launch_configuration`.
  It fires when `metadata_options.http_tokens` is not `required`, and when the block is missing, which is read as optional.
  It works on the mapping form, the one-element list form and CloudFormation `MetadataOptions` and `LaunchTemplateData.MetadataOptions`, and judges every resource on its own.
- **`SG_WEB_PORT_OPEN_TO_WORLD`** (low) and **`SG_TEMPORARY_OPEN`** (low, heuristic).
  The second flags an open group whose name, description or tag value names it as temporary (temp, tmp, debug, remove, delete, todo, test), read word by word, so `TempAllowAll_RemoveMe` matches and `latest-web` does not.
- **`EKS_PUBLIC_ACCESS_ANY_CIDR`** (high, `T1133` and `T1190`) when the public endpoint is on and `public_access_cidrs` has a world CIDR or is unset (the default is `0.0.0.0/0`).
- **`LAMBDA_URL_NO_AUTH`** (high) for `aws_lambda_function_url` with `authorization_type = "NONE"`.
- **`api_gateway.yml`**: `APIGW_METHOD_NO_AUTH` (authorization `NONE`, OPTIONS methods excluded because browsers send CORS preflight requests without credentials), `APIGW_ROUTE_NO_AUTH` (HTTP and WebSocket routes, where an omitted `authorization_type` is `NONE`), `APIGW_PUBLIC_POLICY` (a REST API resource policy that allows Principal `*` with no condition, from the `policy` attribute or an `aws_api_gateway_rest_api_policy`) and `APIGW_NO_ACCESS_LOGS` (REST and HTTP API stages).
- **`ecr.yml`**: `ECR_MUTABLE_TAGS` (`MUTABLE` is also the default), `ECR_NO_SCAN_ON_PUSH` and `ECR_PUBLIC_POLICY`.
  The policy rule reports on the repository: an `aws_ecr_repository_policy` and the CloudFormation `RepositoryPolicyText` are folded into `derived.policy_statements` of the repository.
- **`sagemaker.yml`**: `SAGEMAKER_NOTEBOOK_DIRECT_INTERNET` and `SAGEMAKER_NOTEBOOK_ROOT_ACCESS` (both `Enabled` by default) and `SAGEMAKER_NOTEBOOK_NO_KMS`.
- **`threatcode.ir.enrichment.aws_network`**, the provider module of this family.
  It holds the WAF facts, the resource policy statements of REST APIs and ECR repositories, the temporary marker of security groups, flow logs of subnets, whether an EKS cluster has an IAM OIDC provider, and the `DEFAULTS` table below.
  Every derived key is documented in the module docstring.
- **`DEFAULTS` for these types only**, with the values of the exposure table of WP-3-1: `aws_eks_cluster` `vpc_config.endpoint_public_access` true, `metadata_options.http_tokens` `"optional"` on instances, launch templates and launch configurations when the block exists and does not say, and `aws_lb` `internal` false.
  The graph does not record the input format of its nodes yet (`graph.node_formats` has no producer), so the table is inert until it does; the EKS rules read the default themselves so they do not depend on it.
- **`EKS_NO_IRSA`** is derived from the scan instead of from a computed attribute.
  A provider of the cluster's issuer gives `has_oidc_provider` true.
  The usual `tls_certificate` data source setup, or an EKS issuer written out, makes it unknown, so a cluster that has an OIDC provider by that route is not reported.
  A provider of another identity provider (GitHub's URL) says nothing.

### Changed

- **Calibration** follows the convention of the plan.
  Missing logging controls (`VPC_NO_FLOW_LOGS`, `ELB_NO_ACCESS_LOGS`, `CLOUDFRONT_NO_LOGGING`, `WAF_NO_LOGGING`, `EKS_NO_LOGGING`, `ECS_NO_LOGGING`, `APIGW_NO_ACCESS_LOGS`) are `repudiation`, `absence`, share the root cause `logging-not-enabled` and carry no ATT&CK technique.
  This replaces the retag of `T1562.008` to `T1685.002` that the ATT&CK database change called for: a missing control is not an adversary technique, and no rule of these files uses `T1562.008` any more.
  Customer-managed-key preferences (`EKS_NO_ENCRYPTION`, `SAGEMAKER_NOTEBOOK_NO_KMS`) are low and say "not using a customer-managed key".
  Tactics are derived from the techniques, never written by hand.
- **Techniques follow what the rule proves.**
  Exposed administration and database ports and the open Kubernetes API map to `T1133` External Remote Services, exposed applications to `T1190`, `EKS_OUTDATED_VERSION` to `T1190` instead of `T1195.002`, `ECS_NO_READONLY_FS` to `T1105` instead of `T1565.001`, and `EKS_SSH_ACCESS_NODES` to `T1021.004`.
- **Severity and category.**
  `ECS_PRIVILEGED_CONTAINER` is high (it was critical: a privileged container is a misconfiguration that enables escape, not direct exposure), `EC2_PUBLIC_IP`, `EKS_PUBLIC_ENDPOINT`, `ELB_NO_HTTPS` and `CLOUDFRONT_NO_HTTPS` are medium, `WAF_NO_DEFAULT_BLOCK` (a default Allow with blocking rules is the usual setup) is low and heuristic, and the WAF protections that are missing are medium or low absences.
  `SG_UNRESTRICTED_INGRESS` is `information_disclosure` (it was `spoofing`).
- **The `WAFV2_*` protection rules moved from `aws_wafv2_rule_group` to `aws_wafv2_web_acl`.**
  Managed rule groups can only be used in a web ACL, and a rule group that holds only rate limits is not missing SQL injection protection.
  A rule group is still checked for its rate limit (`WAFV2_RATE_LIMIT_HIGH` covers both) and for being empty.
  The rules that look for a missing protection stay quiet on a web ACL with no rules at all, because `WAF_EMPTY_RULES` already says it.
- `AWSManagedRulesKnownBadInputsRuleSet` counts as a managed rule group but not as SQL injection or cross-site scripting protection, because it holds neither.
  The cross-site scripting protection is `AWSManagedRulesCommonRuleSet` or an `xss_match_statement`, and the SQL injection protection is `AWSManagedRulesSQLiRuleSet` or a `sqli_match_statement`.

### Removed

These rule IDs are recorded in `deprecated_ids` of their files, so a suppression naming one produces a warning.

- `EC2_NO_MONITORING` and `LAMBDA_NO_DLQ`: reliability settings, no attacker technique.
- `EKS_PUBLIC_NODE_GROUP`: whether nodes are public cannot be told from a node group, and its condition was the same as `EKS_SSH_ACCESS_NODES`.
- `EKS_NO_FARGATE_LOGGING`: Fargate logging is an `aws-observability` ConfigMap in the cluster, not an attribute of the profile, and the rule tested a required attribute.
- `EKS_UNENCRYPTED_NODE_AMI`: it fired on every node group without a launch template, although EBS encryption by default or the managed node group's own volume settings may apply.

### Golden recordings

Only the `findings/aws__<group>.json` files of the twelve groups changed, across 29 inputs (52 files changed, 9 new, 5 removed because nothing is reported there any more), and `scripts/check_golden_scope.py` finds nothing outside them.
The changes fall into these kinds.

- **Reliability rules disappear.**
  `EC2_NO_MONITORING` and `LAMBDA_NO_DLQ` are gone from every input that had them.
- **`EC2_IMDSV1` appears on every instance without `metadata_options.http_tokens = "required"`.**
  That includes the IMDSv1 instances of `realistic/04` (`bastion`), `05` (`vpn_concentrator`, but not `internal_proxy`, which sets `required`), `08` (`gpu_experiment_box`) and `10` (`game_server_1`).
- **`SG_UNRESTRICTED_INGRESS` returns on real ingress.**
  `terraform/multi_service_insecure.plan.json` (`wide_open`, SSH), `realistic/04` (`bastion_sg`), `05` (`temp_debug`), `08` (`notebook_debug`) and `10` (`game_server_test_sg`).
  `SG_TEMPORARY_OPEN` accompanies it on 05, 08 and 10.
  `SG_WEB_PORT_OPEN_TO_WORLD` appears on the public load balancer groups of `realistic/01` and `04`, the CloudFormation web stacks, `real_shapes/terraform/plan/webapp.plan.json`, `real_shapes/terraform/hcl/module_app/security.tf` and `multi_service_insecure` (`ipv6_open`, port 80 from `::/0`, and `wide_open`, 443).
- **`VPC_NO_FLOW_LOGS`** loses its technique everywhere.
  It disappears from `real_shapes/terraform/plan/modules.plan.json` and from the root VPC of `module_scopes.plan.json`, whose flow logs it now sees, and it newly appears on `real_shapes/terraform/hcl/module_app/network.tf` (its tags are unresolved, so the old tag test was undecided) and on the two VPCs of `terraform/multi_service_secure.plan.json`, which has no `aws_flow_log` and only a tag.
  The `module_scopes` recording attributes the flow log of `module.net` to the root VPC, because a plan node carries no module and `aws_vpc.main` resolves to the root first.
  That is a defect of the reference resolution, not of this package, and the recording changes with its fix.
- **Lambda.**
  `LAMBDA_OVERPERMISSIVE_ROLE` leaves `terraform/multi_service_insecure.plan.json` and `realistic/01`, where the role is an ARN outside the scan and only its name said admin.
  It appears on the CloudFormation functions whose in-template role has an administrator policy (`sam_function`, `sam_api`, `realistic/03` and `06`).
  `LAMBDA_NO_VPC` drops to low, becomes `information_disclosure` and loses `T1190`.
- **New rules on existing inputs:** `APIGW_PUBLIC_POLICY` (`realistic/06` `BankingApi`), `ECR_MUTABLE_TAGS` and `ECR_NO_SCAN_ON_PUSH` (`realistic/04`, `08`), `ECS_NO_READONLY_FS` and `ECS_NO_LOGGING` (`realistic/04`), `SAGEMAKER_NOTEBOOK_DIRECT_INTERNET` and `SAGEMAKER_NOTEBOOK_ROOT_ACCESS` (`realistic/08`).
- **`CLOUDFRONT_NO_HTTPS` leaves `realistic/01`**, whose hand-built distribution has no `default_cache_behavior` at all, and `CLOUDFRONT_NO_GEO_RESTRICTION` appears there and on `realistic/10`.
- **Severities, categories and techniques follow the calibration above** (every `~` line of the recordings).

On the planted-issue benchmark the recall of the ten realistic inputs rises from 22 of 39 to 29 of 39.
One more resource of the hardened list fires: `aws_instance.web_a` of `realistic/01` sets no `metadata_options`, which is read as IMDSv1.
