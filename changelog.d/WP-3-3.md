## AWS data, identity and logging rules on companion facts and parsed policies (WP-3-3)

### Fixed

- **S3 rules no longer fire on correctly configured provider v4 buckets.**
  `S3_NO_VERSIONING`, `S3_NO_LOGGING` and `S3_NO_ENCRYPTION` read the facts the enrichment layer folds into the bucket (`derived.versioning_enabled`, `derived.logging_enabled`, `derived.sse_algorithm`), so a bucket configured through `aws_s3_bucket_versioning`, `aws_s3_bucket_logging` and `aws_s3_bucket_server_side_encryption_configuration` is judged on its effective configuration in HCL, plan JSON and CloudFormation.
  The companion resources are never reported themselves.
- **`S3_PUBLIC_ACCESS` reads the parsed ACL and policy.**
  It fires on a bucket whose ACL is `public-read`, `public-read-write` or `authenticated-read`, or whose policy has an `Allow` statement for every principal (`"*"`, `{"AWS": "*"}`) with no condition key that names the caller (`aws:PrincipalOrgID`, `aws:SourceVpce`, `aws:SourceVpc`, `aws:SourceArn`, `aws:SourceAccount`, `aws:PrincipalArn`, plus `aws:SourceOwner`, `aws:PrincipalAccount`, the organisation path keys and `kms:CallerAccount`).
  Condition keys are matched without regard to case, as AWS does.
  A public access block stops what it covers: `block_public_acls` or `ignore_public_acls` stops the ACL route, `block_public_policy` or `restrict_public_buckets` stops the policy route, and a partial block stops only its own half.
  The finding sits on the bucket, not on the `aws_s3_bucket_acl` or `aws_s3_bucket_policy` resource that carries the setting.
  A CloudFormation `AWS::S3::BucketPolicy` is matched to its bucket through the reference edge the graph drew from its `Ref`, which the by-value companion join cannot follow.
- **Wildcard IAM is found in every spelling.**
  `IAM_WILDCARD_ACTION` reads parsed statements instead of the policy text, so inline role policies (`aws_iam_role_policy`, `aws_iam_user_policy`, `aws_iam_group_policy`, `inline_policy` blocks and CloudFormation `Policies`), pretty-printed JSON, `["*"]` lists, `jsonencode(...)` and heredocs all count.
  A `Deny` statement never fires, a `NotAction` statement never fires, and a statement that depends on a value the scan does not have is neither a finding nor a pass.
- **Rules that checked attributes that do not exist, or flagged the secure default, are fixed or deleted** (the full list is under Removed and Changed).
  `SM_NO_ROTATION` reads `derived.rotation_enabled`, so a secret with an `aws_secretsmanager_secret_rotation` resource is no longer reported.
  `SM_LONG_ROTATION` lives on the rotation resource, where `rotation_rules` is.
  `CONFIG_NOT_ENABLED` reads `aws_config_configuration_recorder_status.is_enabled`; a recorder with no `recording_group` records everything and is no longer reported.
  `RDS_NO_BACKUP` fires only on an explicit `backup_retention_period` of 0, because an omitted value is 1 day.
  `DYNAMODB_NO_PITR` and the OpenSearch encryption rules see a block that is present with `enabled = false`, which a plan always prints.
- **A database that is a member of a cluster no longer reports missing encryption.**
  `RDS_NO_ENCRYPTION` skips an instance with `db_cluster_identifier`, a restore from `snapshot_identifier`, a replica (`replicate_source_db`, `replication_source_identifier`) and a serverless v1 Aurora cluster, which all inherit the setting.
- **`KMS_KEY_ROTATION_DISABLED` skips asymmetric and HMAC keys**, whose `customer_master_key_spec` is not `SYMMETRIC_DEFAULT` and which cannot rotate automatically.
- **`SSM_UNENCRYPTED_PARAMETER` fires only for a `String` parameter whose name has a secret word** (`password`, `token`, `api_key`, `credential`, `private_key` and similar, split on punctuation and capitals).
  `/prod/region`, `/app/keyboard` and `/app/password_policy` no longer fire.
- **`ELASTICACHE_NO_AUTH` accepts `user_group_ids`** (RBAC) as well as `auth_token`.
- **`SNS_NO_HTTPS` is judged on the subscription.**
  It fires on an `aws_sns_topic_subscription` with protocol `http`; a topic alone no longer reports it.
- **`SQS_NO_ENCRYPTION` passes a queue with `sqs_managed_sse_enabled` set to true.**
- **`CLOUDTRAIL_NOT_ENABLED` fires on `enable_logging = false`** (the attribute defaults to true) and no longer repeats `CLOUDTRAIL_NOT_MULTI_REGION`, which now reads `is_multi_region_trail` with its documented default of false.
  An `Unknown` `kms_key_id` never fires `CLOUDTRAIL_NO_ENCRYPTION`.

### Added

- **`ir/enrichment/aws_data.py`.**
  It holds the provider defaults for `aws_kms_key.enable_key_rotation` (false) and for `aws_cloudtrail.is_multi_region_trail` (false), `enable_log_file_validation` (false) and `enable_logging` (true), each with the documented provider default in a comment.
  It also computes the facts the matcher cannot compute (it has no suffix test, its string comparison is case sensitive and it cannot split a name into words): `allows_all_actions`, `allows_service_wildcard`, `allows_passrole_wildcard`, `admin_policy_attached`, `allows_any_principal`, `secret_name`, and for Redshift `publicly_accessible` and `logging_enabled`.
  The documented list of restricting condition keys is the constant `RESTRICTING_CONDITION_KEYS`.
  A node with nothing to judge, such as a bucket with no policy, carries no fact, and an unreadable policy makes the fact `Unknown`.
- **`S3_PUBLIC_ACCESS_BLOCK_DISABLED`** (medium) on `aws_s3_bucket_public_access_block` and `aws_s3_account_public_access_block`: fires unless all four flags are true.
  A flag that is left out counts as false, as the provider defaults it, so the HCL and plan JSON forms of the same block agree.
- **`IAM_SERVICE_WILDCARD`** (high): every action of one service on every resource (`iam:*` on `*`), or every action (`*`) on a limited set of resources.
  A rule has one severity, so the critical admin pair (`*` on `*`) stays `IAM_WILDCARD_ACTION` and the broad but narrower grants are this rule.
  `s3:*` on one bucket is not reported.
- **`IAM_PASSROLE_WILDCARD`** (high): `iam:PassRole`, or a pattern that covers it such as `iam:Pass*`, on every resource and not narrowed by an `iam:PassedToService` condition.
- **`IAM_ADMIN_POLICY_ATTACHED`** (critical): the AWS managed policy `AdministratorAccess` attached through `aws_iam_role_policy_attachment`, `aws_iam_user_policy_attachment`, `aws_iam_group_policy_attachment`, `aws_iam_policy_attachment`, or listed in the `managed_policy_arns` of a role, user or group, in any partition.
- **Aurora clusters.**
  `RDS_NO_ENCRYPTION` and `RDS_NO_BACKUP` also cover `aws_rds_cluster`, `RDS_PUBLIC_ACCESS` also covers `aws_rds_cluster_instance`, and `RDS_NO_DELETION_PROTECTION` (low) and `RDS_NO_IAM_AUTH` (low) judge the cluster.
- **`aws/redshift.yml`:** `REDSHIFT_PUBLIC_ACCESS` (critical; the Terraform provider defaults `publicly_accessible` to true, a CloudFormation cluster that does not say is not judged), `REDSHIFT_NO_ENCRYPTION` (high; fires on an explicit `encrypted = false`) and `REDSHIFT_NO_LOGGING` (low; counts the inline `logging` block and an `aws_redshift_logging` resource, matched by reference or by literal cluster identifier).
- **`aws_opensearch_domain`** is judged by the three search domain rules, next to `aws_elasticsearch_domain`.
- **Rule examples.**
  Every rule of the fifteen groups has a real-syntax bad and good case in HCL and plan JSON, and in CloudFormation where the type is mapped, under `tests/test_rules/cases/aws__*`.
  The uncovered lists of all fifteen groups are empty.
  `tests/test_engine/test_aws_data_rules.py` is rewritten to run every scenario through the parser, the graph and the engine, including the four policy shapes the audit found invisible, the Deny guardrail, the organisation guard, the asymmetric key exclusion, SQS managed SSE, HCL, plan and CloudFormation parity, Unknown values and mutations of the fact module.
- Every rule of the fifteen groups declares a `confidence`, and the rules that share a fix share a `root_cause`.

### Changed

- **Severity calibration.**
  Absence rules are at most medium, a heuristic is at most high, and critical is definitive only.

  | Rule | Before | After | Why |
  | --- | --- | --- | --- |
  | `S3_NO_ENCRYPTION` | high | low | S3 encrypts every new object with SSE-S3; the rule is now "not encrypted with a customer-managed KMS key" and keeps its id |
  | `CLOUDTRAIL_NO_ENCRYPTION` | high | low | log files use SSE-S3 by default; the rule is the customer-managed key preference |
  | `DYNAMODB_NO_ENCRYPTION` | medium | low | tables are encrypted with an AWS owned key by default; fires without `server_side_encryption.kms_key_arn` |
  | `SQS_NO_ENCRYPTION` | medium | low | the queue is encrypted unless SSE is off; fires without a key and without `sqs_managed_sse_enabled` |
  | `SNS_NO_ENCRYPTION` | medium | low | customer-managed key preference |
  | `SM_NO_KMS_KEY` | medium | low | customer-managed key preference, now maps to T1555.006 |
  | `SM_NO_ROTATION` | high | medium | absence rule |
  | `ELASTICACHE_NO_AUTH` | high | medium | absence rule |
  | `S3_NO_LOGGING` | medium | low | server access logs are a detective gap, not an exposure |
  | `KMS_KEY_ROTATION_DISABLED` | medium | low | hygiene control; no adversary technique |
  | `CLOUDTRAIL_NO_LOG_VALIDATION` | medium | low | detective control |
  | `GUARDDUTY_NO_MALWARE_SCAN` | medium | low | detective control |
  | `SM_LONG_ROTATION` | medium | low | an arbitrary 90 day threshold |
  | `IAM_OVERPERMISSIVE_ROLE` | high | critical | a role anyone can assume is world-open control; keeps its id |
  | `KMS_KEY_EXPOSED` | critical | critical | takes over `KMS_WILDCARD_POLICY`, which had the same condition and a lower severity |
  | `ES_PUBLIC_DOMAIN` | critical | high | heuristic: an absent `vpc_options` does not prove exposure |
  | `IAM_WILDCARD_ACTION` | critical | critical | only for `Allow` with `*` on `*` |

- **STRIDE and ATT&CK.**
  Recoverability controls (`S3_NO_VERSIONING`, `RDS_NO_BACKUP`) use `denial_of_service` like `DYNAMODB_NO_PITR`.
  Missing logging and detection rules use `repudiation` and no adversary technique: `S3_NO_LOGGING`, `SSM_NO_DESCRIPTION`, the CloudTrail, Config and GuardDuty rules and `REDSHIFT_NO_LOGGING`.
  This replaces the revoked T1562.008 on all of them.
  Public data exposure maps to T1530 only (`S3_PUBLIC_ACCESS` loses T1190, which is for exploiting an application), secrets stores to T1555.006 where they mapped to T1530, T1528 or T1552.001, `IAM_OVERPERMISSIVE_ROLE` loses T1098, `KMS_KEY_ROTATION_DISABLED` and `SSM_NO_ALLOWED_PATTERN` lose their techniques, and `GUARDDUTY_NO_MALWARE_SCAN` loses T1587.001, which is a resource development technique.
  The hand-written `tactics:` are gone and derive from the techniques.
- `S3_PUBLIC_ACCESS` applies to `aws_s3_bucket` only; `aws_s3_bucket_acl` is no longer one of its types.
- `ES_NO_ENCRYPTION` and `ES_NO_NODE_TO_NODE_ENCRYPTION` also fire on a block with `enabled = false`.
- `KMS_KEY_ROTATION_DISABLED`, `CLOUDTRAIL_NOT_MULTI_REGION` and `CLOUDTRAIL_NO_LOG_VALIDATION` accept an absent attribute as its provider default, so they work before the graph records which parser produced a node.

### Removed

Each id is recorded in `deprecated_ids` of the file it lived in, so a `.threatcodeignore` line that names one warns instead of silently doing nothing.

- `IAM_NO_MFA`: MFA is not an attribute of `aws_iam_user`, and the rule keyed on `force_destroy` and a tag.
- `KMS_WILDCARD_POLICY`: merged into `KMS_KEY_EXPOSED`.
- `KMS_NO_DELETION_PROTECTION`: `deletion_window_in_days` defaults to 30 days, the longest allowed, so leaving it out is the safest setting.
- `SQS_NO_DLQ` and `DYNAMODB_NO_AUTOSCALING`: reliability settings with no attacker in them.
- `SSM_STANDARD_TIER_SECRET`: a SecureString is KMS encrypted on either tier.
- `CLOUDTRAIL_NO_S3_ACCESS_LOGGING` and `CONFIG_NO_DELIVERY_CHANNEL`: they read a required argument and never fired.
- `CONFIG_NO_AGGREGATION`: the aggregator is the resource being judged, so "no aggregator" cannot be seen, and an organisation aggregator has no `account_aggregation_source` by design.
- `SM_NO_RESOURCE_POLICY`: a secret without a resource policy is governed by identity policies of its own account, the safest default.
