## Azure rules for current provider types with correct network logic (WP-3-4)

### Fixed

- **Network security group rules look at the source and the port.**
  `AZURE_NSG_SSH_OPEN` and `AZURE_NSG_RDP_OPEN` fired for any inbound allow rule on port 22 or 3389, including SSH from `10.50.10.0/24`.
  `AZURE_NSG_ALLOW_ALL_INBOUND` was critical for any rule whose source was `*`, including a rule that opens only 443.
  A rule now fires only for an inbound Allow rule over TCP or any protocol whose source is the whole internet (`*`, `Internet`, `Any`, `0.0.0.0/0`, `::/0`, alone or in `source_address_prefixes`) and whose destination ports overlap the named port, whether written as one port, a range such as `20-25`, a list such as `["3389", "22"]` or `*`.
  Deny rules, outbound rules and UDP or ICMP rules never fire.
  `AZURE_NSG_ALLOW_ALL_INBOUND` needs every port (`*`, `0-65535` or a list holding either).
  Protocol, direction and access are compared case-insensitively.
- **Inline `security_rule` blocks are read.**
  Every rule now also runs on `azurerm_network_security_group` and judges each inline block with `any_item`, so the planted `TempAllowAll_RemoveMe` block in `realistic/07` is found while its `10.50.10.0/24` SSH block is not.
  Rule priority is not evaluated, and the rule descriptions say so.
- **A rule that opens every port is reported once.**
  The SSH, RDP, database and web port rules skip a rule that opens all ports, so one debugging block gives one critical finding instead of four.
- **`MONITOR_NO_DIAGNOSTIC_SETTING` was a false positive on current providers.**
  It fired on every setting that used the `enabled_log` block, because it only looked for `log`.
  It now accepts either block, and fires for a setting that has neither (a metrics-only setting).
  `MONITOR_SHORT_RETENTION` reads both blocks, no longer treats `days = 0` (keep forever) or a disabled retention policy as short, and only looked at the first `log` block before.
- **`KEYVAULT_NO_DIAGNOSTICS` fired on every vault.**
  It read a `diagnostic_settings` attribute that does not exist.
  It now reads `derived.has_diagnostic_settings`, which is true when an `azurerm_monitor_diagnostic_setting` targets the vault.
- **`MSSQL_NO_AUDITING` and `MSSQL_NO_THREAT_DETECTION` fired on every server.**
  They read attributes that live on separate resources.
  They now read `derived.auditing_enabled` and `derived.alert_policy_enabled`, which fold in `azurerm_mssql_server_extended_auditing_policy`, `azurerm_mssql_server_security_alert_policy` and the legacy inline `extended_auditing_policy` block.
- **`MSSQL_NO_TDE` could never fire.**
  It tested `transparent_data_encryption_enabled` on the server, where the attribute does not exist.
  It now runs on `azurerm_mssql_database`, where it fires only when the attribute is explicitly false (the provider default is true).
- **`AZURE_VM_PUBLIC_IP` could never fire.**
  It read the computed `public_ip_address`.
  It now reads `derived.has_public_ip`, joined from the machine's network interfaces through `ip_configuration.public_ip_address_id`.
  An interface the scan cannot see makes the answer unknown, never private, and a conditional address (`var.x ? ... : null`) is not assumed to exist.
- **`AZURE_VM_NO_DISK_ENCRYPTION` tested `managed_disk_type`, which says nothing about encryption.**
  It now reads `encryption_at_host_enabled` and `os_disk.disk_encryption_set_id`, drops to low (managed disks are already encrypted at rest with platform keys) and runs on the Linux and Windows machine types.
- **`APPSVC_OLD_TLS` fired on every app that did not set a TLS version.**
  The provider default is 1.2, so an omitted version is secure.
  It now fires only for an explicit 1.0 or 1.1, in `min_tls_version` or `minimum_tls_version`.
- **`KEYVAULT_NO_NETWORK_ACLS` and `KEYVAULT_PUBLIC_ACCESS` no longer both fire for a vault with a deny-by-default firewall.**
  `KEYVAULT_PUBLIC_ACCESS` needs public network access on and no `network_acls` block or a `default_action` of Allow.
  `COSMOS_PUBLIC_ACCESS` needs no `ip_range_filter` and no virtual network filter.
  `AKS_NO_PRIVATE_CLUSTER` needs no authorized IP ranges.
  `ACR_PUBLIC_NETWORK_ACCESS` and `REDIS_PUBLIC_NETWORK_ACCESS` skip a registry with a deny rule set and a cache injected into a subnet.
- **`AZURE_STORAGE_NO_NETWORK_RULES` ignored `azurerm_storage_account_network_rules`.**
  It read only the inline block.
  It now reads `derived.network_default_deny`, folded from either, and treats a `default_action` of Allow as no restriction.

### Added

- **azurerm 3.x and 4.x types and attribute names.**
  The App Service rules (`APPSVC_*`) run on `azurerm_app_service`, `azurerm_linux_web_app` and `azurerm_windows_web_app`.
  The Function App rules (`FUNC_*`) run on `azurerm_function_app`, `azurerm_linux_function_app` and `azurerm_windows_function_app`.
  The machine rules run on `azurerm_linux_virtual_machine` and `azurerm_windows_virtual_machine`, and the managed identity, public IP and password rules also on the legacy `azurerm_virtual_machine`.
  `AZURE_STORAGE_NO_HTTPS` accepts `enable_https_traffic_only` and `https_traffic_only_enabled`.
  `AZURE_STORAGE_PUBLIC_ACCESS` accepts `allow_blob_public_access` and `allow_nested_items_to_be_public`.
  `APPSVC_NO_AUTH` reads `auth_settings.enabled` and `auth_settings_v2.auth_enabled`.
- **New rule files.**
  `container_registry.yml`: `ACR_ADMIN_ENABLED`, `ACR_PUBLIC_NETWORK_ACCESS` and `ACR_ANONYMOUS_PULL`.
  `redis_cache.yml`: `REDIS_NON_SSL_PORT` (reads `enable_non_ssl_port` and `non_ssl_port_enabled`), `REDIS_OLD_TLS` (explicit 1.0 or 1.1 only, because the provider default changed in 4.0) and `REDIS_PUBLIC_NETWORK_ACCESS`.
- **New rules.**
  `AZURE_NSG_DATABASE_PORT_OPEN` (high) and `AZURE_NSG_WEB_PORT_OPEN` (low) complete the NSG set, the second being the Azure equivalent of the web-port rule in the AWS security group package, so a public web front end is reported without becoming noise.
  `AZURE_STORAGE_CONTAINER_PUBLIC` flags a container whose access type is `blob` or `container`.
  `KEYVAULT_SHORT_SOFT_DELETE_RETENTION` (low) replaces `KEYVAULT_NO_SOFT_DELETE`.
- **Provider defaults for Terraform HCL** (`ir/enrichment/azure.py`, `DEFAULTS`).
  `private_cluster_enabled` false on AKS, `purge_protection_enabled` false and `public_network_access_enabled` true on Key Vault, `allow_nested_items_to_be_public` true on storage accounts, `public_network_access_enabled` true on Cosmos DB, SQL servers, container registries, Redis caches and the new Function App types, and `https_only` false on every App Service and Function App type.
  The values are the azurerm provider defaults and match the exposure table in the graph, and the table lists only types an Azure rule tests.
- **Joined facts.**
  `derived.network_default_deny` on storage accounts and `derived.has_public_ip` on machines, with the unknown-never-private behavior described above.

### Changed

- **Calibration.**
  Every Azure rule declares `confidence`, `root_cause` groups findings with one fix, and no rule carries a hand-written `tactics:` any more (they are derived from the techniques).
  The Azure rules were 2 critical, 21 high, 19 medium and 3 low (45 rules) and are now 2 critical, 15 high, 21 medium and 11 low (49 rules).
  Critical stays on `AZURE_NSG_ALLOW_ALL_INBOUND` (all ports open to the world) and `AKS_NO_RBAC` (RBAC explicitly off), both definitive.
  Absence rules are medium at most: `MSSQL_NO_AUDITING`, `MSSQL_NO_THREAT_DETECTION`, `AZURE_SQL_NO_AUDIT`, `AZURE_SQL_NO_THREAT_DETECTION`, `KEYVAULT_NO_DIAGNOSTICS`, `KEYVAULT_NO_NETWORK_ACLS`, `AZURE_STORAGE_NO_NETWORK_RULES`, `COSMOS_NO_VNET_RULES`, `AKS_NO_NETWORK_POLICY` and the managed identity rules.
  Severity moves: `KEYVAULT_NO_PURGE_PROTECTION` high to medium, `APPSVC_OLD_TLS` high to medium, `AZURE_VM_PASSWORD_AUTH` high to medium, the three `*_NO_MANAGED_IDENTITY` rules medium to low, `FUNC_PUBLIC_ACCESS` medium to low, `AZURE_STORAGE_PUBLIC_ACCESS` high to medium (the account setting only permits public containers), `COSMOS_NO_CMK` medium to low and now worded as a customer-managed key preference, `AZURE_VNET_NO_DDOS` medium to low, `MONITOR_SHORT_RETENTION` medium to low, `AZURE_STORAGE_NO_SOFT_DELETE` medium to low.
  `MSSQL_PUBLIC_ACCESS` stays high but is heuristic: whether the server is reachable depends on firewall rules, which are separate resources.
- **STRIDE and ATT&CK.**
  Missing logging and detection controls (`KEYVAULT_NO_DIAGNOSTICS`, the SQL auditing and threat detection rules, the Monitor rules) are STRIDE repudiation and claim no technique, where they claimed the revoked `T1562.008`.
  Recoverability controls are denial of service.
  Exposed SSH and RDP map to `T1133` with `T1021.004` and `T1021.001`, exposed applications to `T1190`, the DDoS rule to `T1498`, Key Vault network exposure to `T1555.006`, storage and Cosmos DB exposure to `T1530`, and the registry admin account to `T1078.004`.
  Rules with no honest adversary technique (`AKS_NO_NETWORK_POLICY`, `AZURE_VM_NO_DISK_ENCRYPTION`, `COSMOS_NO_CMK`) claim none.
  No Azure rule uses a revoked technique.
- `APPSVC_NO_AUTH` is now `heuristic`: it fires when built-in authentication is explicitly off, which does not prove the application has none.

### Removed

These rule ids are recorded in `deprecated_ids`, so an ignore line that names one is reported as naming a removed rule.

- `KEYVAULT_NO_SOFT_DELETE`: soft delete is mandatory on every Key Vault, so an omitted `soft_delete_retention_days` means the 90 day default.
- `AZURE_VM_NO_EXTENSIONS`: it read `os_profile`, which says nothing about extensions.
- `FUNC_HTTP_V1` and `COSMOS_NO_ANALYTICAL_STORAGE`: HTTP/2 and analytical storage are performance and workload features that give an attacker nothing.
- `AZURE_SQL_PUBLIC_ACCESS` and `AZURE_SQL_NO_ENCRYPTION`: the legacy `azurerm_sql_server` has no `public_network_access_enabled` and `azurerm_sql_database` has no `transparent_data_encryption_enabled`, so neither could ever fire.
  `MSSQL_PUBLIC_ACCESS` and `MSSQL_NO_TDE` cover the current types.
