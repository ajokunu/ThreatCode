## GCP rules that match real Terraform shapes (WP-3-5)

Before this change none of the 35 GCP rules had a bad and good example, and the firewall, Cloud Run, BigQuery and Cloud SQL rules either ignored what they were named for or read properties no parser produces.
Every GCP rule now has a real-syntax HCL case, most also have a plan JSON case, and the GCP uncovered lists are empty.

### Fixed

- **Firewall rules look at the port, the direction and the source.**
  `GCP_FW_SSH_OPEN` and `GCP_FW_RDP_OPEN` were copies of `GCP_FW_ALLOW_ALL` and fired on any rule open to `0.0.0.0/0`, so HTTPS from the internet reported SSH, RDP and "allows all ingress" as critical.
  SSH now needs port 22 and RDP port 3389, in a single port, a `lo-hi` range or a rule that opens every port.
  `GCP_FW_ALLOW_ALL` now needs `all` protocols or every port of `tcp`, `udp` or `sctp` (no `ports`, `0-65535`, or ranges that together cover it).
  A rule without a direction counts as ingress, an egress rule, a disabled rule and a `deny` rule never fire, and `udp` 22 or `icmp` from the world is silent.
  A rule that names no source at all (no `source_ranges`, `source_tags` or `source_service_accounts`) admits every address in Compute Engine and is treated as world-open.
  IPv6 `::/0` counts as the world.
  A port or source nobody set (a variable without a value) never produces a finding.
- **Public access is read from the resources that grant it.**
  `CLOUDRUN_UNAUTHENTICATED` and `BQ_PUBLIC_ACCESS` read the synthetic properties `has_allow_unauthenticated` and `has_public_access`, which no parser emits, so they never fired.
  They now read the facts the enrichment layer folds in from `google_cloud_run_service_iam_member` and `_iam_binding` (and the v2 pair), and from dataset `access` blocks with `special_group`, `iam_member` and the dataset IAM and access resources.
  Cloud Run v2 services are covered.
- **Cloud SQL, Cloud Run and Cloud Functions rules read the settings where Terraform puts them.**
  Nested blocks (`settings`, `ip_configuration`, `template`, `service_config`) resolve the same in HCL and plan JSON.
  `CLOUDRUN_NO_CPU_LIMIT` checks every container, not only the first.
  `CLOUDRUN_NO_VPC_CONNECTOR` also accepts direct VPC egress, and the Cloud Run and Cloud Functions setting rules also read the second-generation layouts.
- **`CLOUDSQL_PUBLIC_IP` means reachable from the internet.**
  It fires on a public IPv4 address (`ipv4_enabled`, true by default) together with an authorized network of `0.0.0.0/0`.
  A public address with no world-open authorized network accepts only the listed addresses and the Cloud SQL connectors, and no longer matches.
- **`CLOUDSQL_NO_SSL` reads `ssl_mode` as well as `require_ssl`.**
  It fires unless `require_ssl` is true or `ssl_mode` is `ENCRYPTED_ONLY` or `TRUSTED_CLIENT_CERTIFICATE_REQUIRED`, because the default accepts unencrypted connections.
- **`CLOUDSQL_NO_BACKUP` skips read replicas**, which cannot hold backups, and fires when the `backup_configuration` block is missing as well as when it is disabled.
- **`GCP_VM_DEFAULT_SA` also fires on an explicit default Compute Engine account** (`...-compute@developer.gserviceaccount.com`).
- **`GCP_VM_PUBLIC_IP` reads every network interface** and `ipv6_access_config`, where it read only the first interface.
- **`GCP_VM_NO_SHIELDED` is about Secure Boot**, the one Shielded VM feature that is off by default, and is retitled to say so.
- **`GCFUNC_HTTP_NO_AUTH` is retitled "HTTP trigger allows plain HTTP" and lowered to low.**
  `SECURE_OPTIONAL` allows plain HTTP; it says nothing about authentication.
  The rule keeps its ID so existing suppressions keep working.
  The real unauthenticated check is the new `GCFUNC_PUBLIC_INVOKER`.
- **`GCFUNC_PUBLIC_INGRESS` applies to HTTP-triggered functions only**, since an event-triggered function has no URL, and treats the default `ALLOW_ALL` as the setting when `ingress_settings` is omitted.
- **`GCP_BUCKET_PUBLIC` also covers bucket IAM bindings and ACL entries.**
  It reads `members` and, on `google_storage_bucket_access_control`, `google_storage_default_object_access_control`, `google_storage_bucket_acl` and `google_storage_default_object_acl`, the `entity` and `role_entity` entries naming `allUsers` or `allAuthenticatedUsers`.
- **`GCP_IAM_ADMIN_SA` covers every scope.**
  It reads `roles/owner` and `roles/editor` on project, folder and organization members and bindings, where it read only `google_project_iam_member`, and its title no longer claims the principal is a service account.
- **`GCP_IAM_SA_KEY` fires on a key Terraform generates**, whose private key lands in the state file, and not on a key whose public half you upload with `public_key_data`.
- **`BQ_NO_ACCESS_POLICY` counts companion grants as an access policy.**
  A dataset whose access comes from `google_bigquery_dataset_access` or a dataset IAM member no longer fires it, and neither does one with only `view`, `dataset` or `routine` access blocks.
- **`GKE_NO_NETWORK_POLICY` accepts Dataplane V2** (`datapath_provider = "ADVANCED_DATAPATH"`) as enforcement.
- **`GKE_NO_PRIVATE_CLUSTER` reads `enable_private_nodes`**, where it only checked that a `private_cluster_config` block existed.

### Added

- **Eight rules.**
  `GCFUNC_PUBLIC_INVOKER`: allUsers or allAuthenticatedUsers may invoke a Cloud Function, first or second generation.
  `GCP_IAM_PUBLIC_MEMBER`: allUsers or allAuthenticatedUsers on a member or binding of 38 IAM resource types (project, folder, organization, KMS, Pub/Sub, Secret Manager, service account, Artifact Registry and others); buckets, datasets, Cloud Run services and Cloud Functions keep their own rules.
  `GCP_IAM_SA_TOKEN_CREATOR`: `roles/iam.serviceAccountTokenCreator` granted above a single service account.
  `GKE_NO_MASTER_AUTHORIZED_NETWORKS`, `GKE_MASTER_WORLD_ACCESS`, `GKE_NO_WORKLOAD_IDENTITY`, `GKE_NO_SHIELDED_NODES` and `GKE_NODE_DEFAULT_SA` (node pools).
- **`ir/enrichment/gcp.py`.**
  It derives `ingress_allow` and `world_source` for `google_compute_firewall` under the reserved `derived` namespace, because the matcher reads ports from `port_range` and `from_port`, not from GCP's `ports` list, and because direction, `disabled`, `deny` and an empty source are defaults that no single attribute shows.
  It adds no `DEFAULTS` table: the rules state provider defaults as negations (public IP unless `ipv4_enabled` is false, plain HTTP and `ALLOW_ALL` unless restricted), which also covers a parent block that is omitted, where a nested default cannot fill.

### Known limit

- **A public grant on a resource the scan cannot see is not reported.**
  `CLOUDRUN_UNAUTHENTICATED`, `GCFUNC_PUBLIC_INVOKER` and `BQ_PUBLIC_ACCESS` fire on the service, function or dataset through the grants folded into it, and `GCP_IAM_PUBLIC_MEMBER` leaves those grant types out so a grant is not reported twice.
  An `allUsers` grant on a Cloud Run service, function or dataset defined outside the scanned input therefore produces no finding.
  Bucket grants differ: `GCP_BUCKET_PUBLIC` fires on the grant itself.

### Changed

- **Calibration.**
  Every GCP rule declares a confidence and shares a `root_cause` with its siblings.
  Critical stays only on `GCP_FW_ALLOW_ALL`, `BQ_PUBLIC_ACCESS` and `GCP_BUCKET_PUBLIC`, all definitive direct exposure.
  Customer-managed key preferences (`CLOUDSQL_NO_ENCRYPTION`, `BQ_NO_ENCRYPTION`, `PUBSUB_NO_ENCRYPTION`) are low with "not using a customer-managed key" wording and no adversary technique.
  Rules that fire because something is missing are absence rules and none is above medium: `CLOUDSQL_NO_BACKUP` and the GKE hardening rules are medium, the hygiene rules are low.
  `GKE_NO_PRIVATE_CLUSTER` is medium (was high) and `CLOUDRUN_NO_MAX_INSTANCES` is low (was medium).
  Recoverability controls (`CLOUDSQL_NO_BACKUP`, `GCP_BUCKET_NO_VERSIONING`) use denial of service, where bucket versioning was tampering.
  Missing bucket logging is repudiation with no technique, replacing the revoked `T1562.008`.
  Internet-facing SSH and RDP map to `T1133`, `GCP_VM_NO_SHIELDED` and `GKE_NO_SHIELDED_NODES` to `T1542.003`, `GKE_NO_NETWORK_POLICY` to `T1046`, `GKE_NO_WORKLOAD_IDENTITY` to `T1552.005`, and `CLOUDRUN_UNAUTHENTICATED` to `T1190`.
  `T1499` is gone from the hygiene rules, and the hand-written `tactics` lists are gone: tactics follow from the techniques.
- **`CLOUDRUN_NO_CPU_LIMIT` is a low rule about writing the limit down.**
  Cloud Run applies a default of one CPU, so an unset limit does not mean unbounded usage.

### Removed

- **`BQ_NO_LOCATION`, `PUBSUB_NO_DEAD_LETTER` and `PUBSUB_NO_RETENTION`.**
  A dataset in the default region, a missing dead letter topic and a missing retention window are reliability or residency choices that let an attacker do nothing.
  The IDs are recorded under `deprecated_ids` in their rule files, which is what the suppression loader reads to tell a removed rule from a mistyped one.

### Golden recordings

`real_shapes__terraform__plan__gcp_network.plan.json` is the one shipped GCP input, so two findings files change, and every difference is a consequence of the above.

- `findings/gcp__network.json`: `google_compute_firewall.ssh` allows only tcp 22 from `0.0.0.0/0`, so `GCP_FW_ALLOW_ALL` (critical) and `GCP_FW_RDP_OPEN` (high) are gone and `GCP_FW_SSH_OPEN` remains with technique `T1133` in place of `T1021`.
  `google_compute_firewall.internal` (icmp from `10.40.0.0/24`) stays silent.
- `findings/gcp__compute.json`: `GCP_VM_NO_SHIELDED` on `google_compute_instance.vm` changes its technique from `T1195.002` (a software supply chain technique) to `T1542.003` (bootkit).
  `GCP_VM_DEFAULT_SA` and `GCP_VM_PUBLIC_IP` are unchanged.
- No `graph.json`, `model.json` or other findings file changes, which `scripts/check_golden_scope.py` confirms.
