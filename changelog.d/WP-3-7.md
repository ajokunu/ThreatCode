### Added

- **Secrets are placed on the resource that holds them.**
  The secret detectors now run over the text of every modeled file: Terraform `.tf`, `.tf.json`, the `*.tfvars` files beside a module, Terraform plan JSON, CloudFormation templates, Kubernetes manifests, and Helm charts (`values*.yaml` and the raw `templates/`).
  Each match is a finding with `source` `secret`, rule id `SECRET_<KIND>`, STRIDE information disclosure and ATT&CK `T1552.001`.
  Its `resource_address` is the innermost resource whose lines contain the secret, so a `MasterUserPassword` in a CloudFormation template lands on the Redshift cluster or RDS instance and joins the graph and the attack paths.
  A secret outside every resource (a variable default, a `*.tfvars` entry, Helm `values.yaml`) has an empty address.
  `metadata` carries the `attribute` (the key the value sits under), the redacted `preview` and a `fingerprint_hint`.
- **Kubernetes Secret `data` is decoded and scanned.**
  The base64 values of a Secret manifest are decoded and judged like any other text, so `data.password` is found and the encoded text itself is not reported.
- **Terraform plan JSON is attributed by address.**
  A plan repeats a resource in `planned_values`, `resource_changes` and `configuration`.
  The nearest `address` decides which resource a line belongs to, and repeats of the same value on one resource collapse into one finding with an `occurrences` count.
- **Dockerfiles and MCP configs are not scanned twice.**
  `DOCKER_ENV_SECRET`, `DOCKER_ARG_SECRET` and `MCP_SECRET_IN_CONFIG` already cover them with the same detectors, so the new pass leaves them alone.
- **New detectors.**
  URL userinfo (`scheme://user:pass@host`, database schemes as `SECRET_DB_CONNECTION_STRING` and every other scheme as `SECRET_URL_CREDENTIALS`), `Authorization: Bearer|Basic` headers, .NET and ODBC `Password=...;` connection strings, PKCS#8 and `ENCRYPTED PRIVATE KEY` blocks, GitHub `gho_`, `ghu_`, `ghr_` and `github_pat_` tokens next to `ghp_` and `ghs_`, AWS `ASIA` temporary keys next to `AKIA`, Google `AIza` API keys, Anthropic `sk-ant-` keys, OpenAI `sk-proj-`, `sk-svcacct-` and `sk-admin-` keys, Hugging Face `hf_` tokens, Slack `xapp-` tokens and incoming webhook URLs (`SECRET_SLACK_WEBHOOK`), Azure storage account keys, and `.npmrc` `_authToken` values.
- **Optional high-entropy fallback.**
  `SECRET_HIGH_ENTROPY` is off by default and turns on with `entropy_threshold` in the `secrets` configuration.
- **A `SecretScanConfig` for the `secrets` configuration section** (`allow_patterns`, `extra_rules`, `disabled_rules`, `max_file_size`, the per-file and per-rule caps, `entropy_threshold`) and `SecretScanConfig.from_mapping`.
  `find_secrets(units, graph, config=None)` accepts it.
  The pipeline does not pass one yet, so a `.threatcode.yml` found inside a scanned repository can never switch off that repository's own secret detection.

### Changed

- **Keyword prefilter is case-insensitive.**
  Keywords are lower-cased when a rule is built and compared with the lower-cased text, like the `(?i)` regexes behind them.
  A file holding only `MasterUserPassword: "..."`, `ADMIN_PASSWORD=...` or `"Password": "..."` is no longer skipped.
- **Generic rules read dotenv, YAML, JSON, HCL, shell and source forms.**
  The password, API key and secret or token rules accept unquoted values, quoted values and JSON keys (`"password": "..."`), capture the value in a named group `secret`, and need a minimum length and character mix.
  Values that are Jinja or Go template markers (`{{ }}`, `{% %}`), `${VAR}` or `$(cmd)` substitutions, bare environment variable names (`ANTHROPIC_AUTH_TOKEN`), Terraform references (`var.x`, `random_password.db.result`), file paths, URLs and the placeholders `changeme`, `example`, `your_*`, `<...>` and masks such as `(sensitive)` are not secrets.
- **Allow-lists look at the captured value only.**
  `latest-prod` in a host name, `localhost` elsewhere in a URL and `Test` in a key name such as `TestPassword` no longer suppress a real secret.
  A placeholder word suppresses only when it is the whole value.
  Local database URLs are allow-listed by their host component alone.
- **Stripe test-mode keys are no longer matched on purpose.**
  Only `sk_live_` and `rk_live_` keys are secrets; `sk_test_`, `pk_test_` and the publishable `pk_live_` keys are not.
- **The GCP service account rule needs a `private_key` field.**
  A stub that only names `"type": "service_account"` is not a credential.
- **Database URLs need a password.**
  `SECRET_DB_CONNECTION_STRING` used to flag any database URL; it now requires `user:password@`.
- **Overlapping matches report the more specific rule.**
  A provider token wins over a URL or header credential, which wins over a generic `key = value`.
- **Line numbers split on newline only.**
  A form feed or a Unicode line separator inside a line no longer shifts the numbers of the lines after it.
- **UTF-16 files are decoded.**
  A byte order mark, or the alternating NUL pattern of UTF-16 written without one, selects the codec; other files with NUL bytes are skipped as binary.
- **Findings are capped.**
  At most 100 per file and 25 per rule are listed, the last finding carries `truncated: true`, and a `secrets.truncated` warning is added to the coverage diagnostics.
  A file over `max_file_size` (5 MB by default) or one that cannot be opened is reported as a `secrets.file_skipped` diagnostic instead of being skipped silently.
- **Files are read only through discovery units, and only if regular.**
  A file found by walking is opened with `O_NOFOLLOW` and checked with `fstat`, so a link created after discovery, a FIFO or a device is never read.
  A symlink the user names directly is still followed.
- **Finding ids are deterministic.**
  They are derived from the rule, the root-relative file, the line and the position on the line, never from the checkout location or a random number.
  The fingerprint hint is built from the rule, file, resource and attribute, or from the line with the secret masked, and never from the value.

### Security

- **Previews never contain secret characters.**
  The old preview showed the first and last four characters of the whole match, including a quote and key name, which leaked trailing secret characters.
  A preview is now `[REDACTED <rule id> len=<n>]` and a property test checks that no four-character substring of the secret appears in it.
- **The MCP key and value scorer follows the new detectors.**
  `parsers/_mcp_secrets.py` runs only the provider-token rules on a `key=value` pair, applies the allow-list to the captured token, and compares keywords case-insensitively.
  A key such as `TEST_GITHUB_TOKEN` no longer hides a real token.

### Removed

- `SecretFinding`, `VulnerabilityFinding`, `LicenseFinding`, `ScanReport` and `FindingType` (`models/finding.py`).
  Secret findings are `Threat` objects.
- The directory walker, `skip_paths` and fnmatch skip matching of the old `SecretScanner`.
  Discovery owns the walk, so the segment-anchored skip, dot-directory, symlink and special-file concerns are closed by construction.
