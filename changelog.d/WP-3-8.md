### Changed
- **The Anthropic client works with current models.**
  The default model is now `claude-sonnet-5-5` (the installed SDK lists it among its known model ids; the live models list could not be checked without an API key, so run `threatcode scan --llm` once with a key to confirm it).
  The reply is the joined text of every text block, so thinking blocks no longer break the parse.
  A refusal, or a reply without text, is an `LLMError`.
  A reply cut off at `max_tokens` logs a warning and keeps every complete finding.
  `llm.temperature` is unset by default and sent only when you set it; a model that rejects it gets one retry without it.
  `ANTHROPIC_BASE_URL` and `llm.base_url` go through the same address check as the other providers, so an environment variable can no longer point the SDK at a private or metadata address.
  `llm.allow_local_network` is now also accepted for the `anthropic` provider, for a gateway on a private network.
- **The OpenAI-compatible client is safer and more robust.**
  The key comes from `llm.api_key`, else from the variable named by the new `llm.api_key_env` (default `OPENAI_API_KEY` for `openai`, none for `ollama` and `local`).
  With no key no `Authorization` header is sent.
  HTTP 429, 500, 502, 503 and 504 are retried with exponential backoff and jitter (at most three attempts, `Retry-After` honored up to 30 seconds), and timeouts and socket errors are `LLMError`, not bare exceptions.
  A redirect to another scheme, host or port is refused, so the API key and the request body are never forwarded; a redirect inside the same origin is followed after the usual address check.
  `max_completion_tokens` is sent to `api.openai.com` and `max_tokens` to every other server.
  The `openai` provider defaults its base URL to `https://api.openai.com`.
- **Requests are never cut.**
  A prompt over the client limit is refused with an error instead of being sliced into invalid JSON.
  The new `llm.max_input_tokens` (default 60000, estimated as characters / 3.5) caps the request; the infrastructure context is summarized first (large groups of alike resources become one line, `900 x aws_subnet in zone private`), then resources without findings lose their properties, then whole low-value resources are dropped with their edges.
  What was summarized or dropped is counted in the `llm.context` block of the report and logged as a warning.
  If the context still does not fit, the LLM step fails with a clear error and the rule results are kept.
- **What the model sees is pseudonymous and allowlisted.**
  Every resource is an opaque handle such as `aws_s3_bucket.n3`; names never leave the machine and the answer is mapped back locally.
  Each resource carries its zone, exposure, boundary, evidence level, the ids of the rules that already fired on it, and a small allowlisted set of security properties (ingress and egress CIDRs and ports, IAM effects, actions and principals, encryption and public-access flags, listener protocols, Kubernetes and MCP flags).
  Every other property is dropped.
  Each edge carries its type, the zones it joins, whether it crosses a trust boundary and the declared protocol, ports, authentication and encryption.
  The prompt now says that a resource with `evidence: design` is declared, not verified.
  The data sits inside a delimiter tag with a random per-request suffix, with `<`, `>` and `&` escaped in the JSON, so a resource label cannot close it.
- **The redactor catches more and fails closed.**
  Keys are matched by substring (`db_password`, `aws_secret_access_key`, `user_data`, `client_secret`, `bucket_key` variants and anything with token, credential, authorization, connection, private, certificate or cookie in the name), not by exact name.
  Values are scanned for cloud keys, GitHub, GitLab, Slack, Stripe and Anthropic tokens, JWTs, PEM blocks, webhook URLs and `scheme://user:pass@host` userinfo, whatever key they sit under.
  Bare 12-digit account ids next to a condition word and compressed IPv6 addresses are redacted; `0.0.0.0/0` and `::/0` stay readable because they matter to the analysis.
  `redaction.fields` now works: the listed names are redacted at any depth, case-insensitively, and win over the allowlist.
  Past 10000 distinct values redaction fails closed and nothing is sent, instead of giving different values the same placeholder.
  The `hash` strategy is now an HMAC keyed with a random per-run key and keeps 64 bits, so a provider cannot confirm a guess by hashing it.
  Placeholders are written back into a finding only when they were issued for that finding's own resource and name a location (ARN, address, account); a secret placeholder in model text stays a placeholder.
- **Model output is cleaned and attributed.**
  Titles, descriptions and mitigations lose links, code blocks and shell operator runs and are length capped (200, 2000 and 1000 characters).
  A finding that names no resource of the scan, or one the scan does not have, is no longer reported: it goes to `llm.unattributed` in the report.
  `resource_type` comes from the graph, tactics are derived from the techniques, and a finding that restates a rule, boundary, secret or scanner finding on the same resource and STRIDE category (shared technique or similar title) is dropped.
  The id hashes the resource, the category and the sorted techniques, so a reworded title keeps its id and a baseline diff stays quiet.
  Revoked ATT&CK ids from the model (for example `T1562.008`) map to their successors instead of being dropped.
- **A malformed reply costs only the malformed item.**
  Every field is type-checked, each item is validated on its own, a non-JSON reply logs a warning, and a reply cut off mid-array keeps every complete item.
- **`--dry-run` shows the real request.**
  The exact system prompt and user message, after pseudonymization and redaction, are written as JSON to `--dry-run-output FILE`, or to stderr when no file is given (stdout carries the report), with sizes and the token estimate on stderr.
  The dry run opens no connection.
- **A scanned repository can no longer weaken redaction.**
  `redaction` is no longer read from an auto-discovered `.threatcode.yml`; name the file with `--config` to choose the strategy or add fields.
- **New `llm` config keys:** `api_key_env`, `timeout`, `max_retries` and `max_input_tokens`; `temperature` is now optional (default unset).
  Unknown keys and out-of-range values name the key.
- The `report.llm` block gained `redaction`, `context`, `prompt_hash` (stable across runs for the same input), `input_tokens_estimate`, `parsed_count`, `skipped_items`, `salvaged_items`, `duplicate_count`, `unattributed_count` and `unattributed`.

### Fixed
- `mypy` no longer fails on `engine/llm/client.py`: `temperature` is passed by keyword to SDKs that still take it and in the request body to SDKs that no longer list it.
- The warning about an `api_key` stored in a config file names the variable for the configured provider.

### Golden recordings
- None changed. The golden harness never runs the LLM, and `tests/test_ir/test_golden.py` passes unchanged.

### Carryover from earlier waves closed here
- `BaseLLMClient` has `provider` and `model` attributes (concrete defaults, so a client that sets neither still works), and the status block reads them instead of guessing from class names; an OpenAI-compatible client reports `ollama` or `local` when that is the configured provider.
- The redactor treats `source_file`, `start_line` and `end_line` as sensitive keys, in case they are ever added to the graph payload.
- The response parser calls `normalize_technique` before checking the technique database, so an aliased id maps to its successor.
- `DryRunLLMClient` and the factory write the exact redacted request to `--dry-run-output`.
- The two `mypy` errors at `engine/llm/client.py` line 200 (`temperature` against the installed SDK) are gone, so `mypy src/threatcode` passes.
- `redaction.fields` is passed to the redactor (it was ignored), and its default list is a subset of the built-in sensitive names, so it only starts to matter once you add your own.
